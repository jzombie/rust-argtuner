# Plan: Fix global `q`/`h` key starvation — structural core-vs-app window gate

## Root cause
`AppState::handle_app_event` (src/tui/mod.rs:605) runs **before** every layer in term-wm's runner (runner.rs:456), including direct-mode PTY forwarding. It intercepts `TermWmAction::Quit` (`q`) and `TermWmAction::Custom(1)` (`h`) globally with no focus check, so keystrokes are stolen from any core window that owns its own input (Terminal PTYs — spawnable via the command palette through the delegated `wm_new_terminal()`, src/tui/mod.rs:654 — and potentially other core surfaces).

## Decision: no framework addition needed
`AppRootComponent<C>` (term-wm/src/components.rs:9) has exactly two public variants: `Core(CoreWmComponent)` and `Custom(C)`. ArgTuner's own panes are `Custom`; every framework/system surface (Terminal, Debug Log, System Panel, SessionManager, Noop) is `Core`. So the app can structurally discriminate with a one-line match — **no term-wm change required**. (If ergonomics are desired later, a small `AppRootComponent::is_custom()`/`is_core()` helper could be added to term-wm, but it is not necessary now.)

## Behavior
App shortcuts (`q`, `h`) now fire **only while an app-owned (`Custom`) window is focused**. When a core window holds focus, the app defers entirely to `self.inner.handle_app_event(event)`, so the core window (and, for a PTY, the child process) gets the key. Consequences:
- Terminal focused → `q`/`h` reach the shell/pager/editor (bug fixed).
- Debug Log / System Panel focused → `q`/`h` are no longer intercepted by the app; the core window handles them. Focus an app pane to quit. This is the intended consequence of the structural gate (core windows own their input).

### 2. Helper: `pressed_key` (unchanged from prior round)
```rust
/// Returns the pressed key for key events; None for repeat/release or
/// non-key events. Single match-guard form is stable on pre-1.88 toolchains.
fn pressed_key(event: &Event) -> Option<&KeyEvent> {
    match event {
        Event::Key(key) if key.kind == KeyKind::Press => Some(key),
        _ => None,
    }
}
```

### 3. New method: `focused_window_is_app`
```rust
impl AppState {
    /// True when the focused window is app-owned (AppRootComponent::Custom).
    /// Core/system windows (Terminal, Debug Log, System Panel, …) own their
    /// own input, so the app must not intercept global shortcuts for them.
    fn focused_window_is_app(&mut self) -> bool {
        let wm = self.inner.wm();
        matches!(
            wm.component_for_key(wm.focused_window()),
            Some(AppRootComponent::Custom(_))
        )
    }
}
```
(`wm()` needs `&mut self`; the `&mut` borrow ends when the method returns the `bool`.)

### 4. Rewrite `handle_app_event`
```rust
fn handle_app_event(&mut self, event: &Event) -> bool {
    // filter keeps this a single if-let: no let-chains (pre-1.88 stable) and
    // no `clippy::collapsible_if` from nesting an if inside an if-let.
    if let Some(key) = pressed_key(event).filter(|_| self.focused_window_is_app()) {
        let kb = self.inner.wm().keybindings();
        if kb.matches(TermWmAction::Quit, key) {
            self.open_exit_confirm();
            return true;
        }
        if kb.matches(TermWmAction::Custom(1), key) {
            self.chart_mode = match self.chart_mode {
                ChartMode::Metrics => ChartMode::HyperParams,
                ChartMode::HyperParams => ChartMode::Metrics,
            };
            self.apply_chart_mode();
            return true;
        }
    }
    self.inner.handle_app_event(event)
}
```
