# Plan: Fix global `q`/`h` key starvation for Terminal panes + stable-safe key handling

## Root cause
`AppState::handle_app_event` (src/tui/mod.rs:605) runs **before** every layer in term-wm's runner (runner.rs:456), including direct-mode PTY forwarding. It intercepts `TermWmAction::Quit` (`q`) and `TermWmAction::Custom(1)` (`h`) globally, with no focus check. A Terminal/PTY window (`CoreWmComponent::Terminal`) can be spawned from the command palette via the delegated `wm_new_terminal()` (src/tui/mod.rs:654). When such a pane holds focus, every `q`/`h` keypress is swallowed and opens the exit-confirm instead of reaching the shell/pager/editor. Verified reachable: `component_for_key(&self, WindowKey) -> Option<&C>` (window_manager/mod.rs:2319) and `focused_window()` (focus.rs:17) exist; `CoreWmComponent` is re-exported from `term_wm_ui_facade` (lib.rs:5).

Note: the flagged `if let ... && ...` let-chain compiles fine (crate is edition 2024; let-chains stable since Rust 1.88) — it is refactored anyway for consistency with this repo's pre-1.88-toolchain stance and to keep clippy clean. The pre-existing let-chain in `refresh_trials` is out of scope.

## Changes — all in `src/tui/mod.rs`

### 1. Imports
- Add `CoreWmComponent` to `use term_wm_ui_facade::{LayerComponent, OverlayComponent};` → `use term_wm_ui_facade::{CoreWmComponent, LayerComponent, OverlayComponent};`
- Add `KeyEvent` to `use term_wm::events::{...}` (the `Key` bound by `Event::Key(key)` is `KeyEvent`, defined in term-wm-events). If `term_wm::events` does not re-export it, import from `term_wm_events`.

### 2. Helper: `pressed_key`
```rust
/// Returns the pressed key for key events; None for repeat/release or
/// non-key events. Single if-let keeps this stable on pre-1.88 toolchains.
fn pressed_key(event: &Event) -> Option<&KeyEvent> {
    match event {
        Event::Key(key) if key.kind == KeyKind::Press => Some(key),
        _ => None,
    }
}
```
(Replaces the let-chain guard; match-guard form is not a let-chain and does not trigger `clippy::collapsible_if`.)

### 3. Rewrite `handle_app_event` — gate on Terminal focus
```rust
fn handle_app_event(&mut self, event: &Event) -> bool {
    if let Some(key) = pressed_key(event) {
        // A Terminal pane is a live PTY (spawnable via the command palette):
        // its raw key bytes must reach the child, never be stolen for app
        // shortcuts. Gate Quit/Custom(1) on focus so q/h pass through.
        let is_terminal = {
            let wm = self.inner.wm();
            matches!(
                wm.component_for_key(wm.focused_window()),
                Some(AppRootComponent::Core(CoreWmComponent::Terminal(_)))
            )
        };
        if !is_terminal {
            let kb = self.inner.wm().keybindings();
            if kb.matches(TermWmAction::Quit, key) {
                self.open_exit_confirm();
                return true;
            }
            if kb.matches(TermWmAction::Custom(1), key) {
                self.chart_mode = match self.chart_mode {
                    ChartMode::Metrics => ChartMode::HyperParams,
                    ChartMode::HyperParams => ChartMode::Metrics,
                };
                self.apply_chart_mode();
                return true;
            }
        }
    }
    self.inner.handle_app_event(event)
}
```
- Gate is `not a Terminal`, deliberately **not** "an argtuner window": `q`/`h` must keep working when the (non-PTY) Debug Log / System Panel windows hold focus, preserving current UX.
- The `is_terminal` computation is block-scoped so the `&mut` borrow from `self.inner.wm()` ends before `self.open_exit_confirm()`/`self.apply_chart_mode()`.

### 4. Unit test
Add a small `#[cfg(test)] mod key_tests` in `src/tui/mod.rs` covering `pressed_key`:
- `Event::Key(KeyEvent::new(KeyCode::Char('q'), KeyModifiers::NONE, KeyKind::Press))` → `Some`.
- Same event with `KeyKind::Repeat` / `KeyKind::Release` → `None`.
- A non-key `Event` variant → `None` (use whatever non-key variant is constructible, e.g. a mouse event).
