## Item 4 — Conditional hyperparameters
- **Gap:** `ParamSpec`/`ParamHint` are strictly flat (`[[space.params]]`); there's
  no way to express dependencies (e.g. `learning_rate`/`momentum` exist only
  when `optimizer == "sgdt"`).
- **Impact:** downstream scripts must accept irrelevant args, and samplers waste
  trial budget on parameter combinations that don't affect the objective.
- **Remediation:** extend `ParamSpec`/`ParamHint` with dependency conditions
  (`parent = "optimizer"`, `parent_values = ["sgdt"]`):
  - deserialize/serialize in the search space (`parent` + `parent_values`);
  - conditional sampling — inactive params aren't sampled, and their values
    aren't injected into the rendered command or `hp.*` fields;
  - `validate` rejects a value for a param whose parent condition is unmet;
  - `render_template_command`/`render_space_section` handle conditional params;
  - `inspect` shows the dependency.

## Item 5 — Process-tree hygiene & trial timeouts (zombie risk)
- **Gap (verified):** `src/command/subprocess/runner.rs` spawns children via
  PTY/pipes with **no** process-group management (`setpgid`/`killpg` on Unix, Job
  Objects on Windows), and there is **no per-trial timeout** anywhere
  (tuner/objective). Cancelling or interrupting a trial (e.g. via `Ctrl-C`, the
  TUI, or a future timeout) kills only the direct child.
- **Impact:** orphaned sub-child processes (PyTorch workers, multi-GPU spawned
  workers) keep running and burning CPU/GPU memory after a trial abort.
- **Remediation:**
  - spawn each trial in its own process group (Unix `setpgid`/`killpg`,
    Windows Job Objects — or the `command-group` crate);
  - on timeout/cancel/exit, kill the entire group;
  - add a per-trial timeout (config-driven, e.g. `[scheduler] trial_timeout_s`).

## Item 6 — Multi-objective optimization
- **Gap:** the protocol (`src/command/objective.rs`) and storage
  (`src/trial/`) treat trial results as a single scalar metric (`metric_key`).
- **Impact:** no trade-off optimization (e.g. accuracy vs. latency vs.
  model_size).
- **Remediation:** multi-scalar objectives end-to-end:
  - talkback protocol emits multiple named metrics (already possible via
    `metric.*` fields, but scoring is single-key);
  - sampler/scheduler traits support multi-objective evaluation;
  - Pareto-front tracking (e.g. an NSGA-II sampler) instead of a single
    best-score.
