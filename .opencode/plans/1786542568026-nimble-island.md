# Plan: Add a native `Bool` search-space type

## Goal
`#[talkback_args] struct Params { use_dropout: bool }` should produce a tunable
boolean that serializes as `[[space.params]] type = "Bool" name = "use_dropout"`.
Today `bool` fields are clap presence flags (`--flag`, SetTrue) and are excluded
from the search space; the workaround is `Choice ["true", "false"]`.

New behavior: `bool` fields become value-taking CLI args (`--use-dropout true|false`,
with `#[param(default = ...)]` or required) and tunable `Bool` space params.
(No existing example/field in the repo uses a `bool`, so this is safe.)

## Changes

### 1. `src/search_space/mod.rs` — `ParamSpec::Bool`
- Add `Bool { name: String }` to `ParamSpec`, `ParamSpecPre` (untagged), and
  `TaggedParamSpec` (tagged, `type = "Bool"`), plus the `From` conversion arm.
- Handle `Bool` in every `match`:
  - `name()` → `name`.
  - `validate_spec()` → `Ok(())`.
  - `validate(&str)` → `value == "true" || value == "false"`.
  - `value_from_unit(coord)` → `if c < 0.5 { "false" } else { "true" }`.
  - `discrete_value_count()` → `Some(2)`.
  - `discrete_values()` → `Some(vec!["false", "true"])`.

### 2. `src/sdk.rs` — `ParamKind::Bool`, drop `ParamKind::Flag`, add `skip`
- Replace `ParamKind::Flag` with `ParamKind::Bool`.
- Add `skip: bool` to `ParamHint`.
- `is_tunable()`: `Bool => !p.skip`; `Float|Int => min && max && !skip`; `Choice => !choices.is_empty() && !skip`.
- `SpaceParam` (serde enum): add `Bool { name: &'a str }`.
- `SpaceParam::from_hint`: `ParamKind::Bool => Some(SpaceParam::Bool { name: p.name })`;
  drop the `Flag` arms.
- `render_template_command`: remove the `ParamKind::Flag` bare-`--flag` branch
  (bools render `--flag {placeholder}` via the tunable branch, or `--flag <default>`
  when skipped with a default).

### 3. `crates/argtuner-derive/src/lib.rs` — `bool` fields as flag-friendly value args
- `kind`: `is_bool` → `::argtuner::ParamKind::Bool`.
- Parse `#[param(skip = true)]` (new `ParamAttrs.skip`); emit `skip` in `ParamHint`.
- `command()` for a `bool` field (tunable or skipped) keeps flag ergonomics:
  `.value_parser(::argtuner::clap::value_parser!(bool)).num_args(0..=1).default_missing_value("true")`
  plus `.default_value(...)` (from `#[param(default)]`) or `.required(true)`. So
  `./binary --use-dropout` → `true`, `--use-dropout false` → `false`.
- `from_matches`: `m.get_one::<bool>(id).copied().expect("--flag")` (present via
  default/missing/required) or `.cloned()` for `Option<bool>`.
- Remove the `SetTrue`/`get_flag` special-case; `is_bool` used only for kind.
- `Option<bool>` still unwraps to inner `bool`, kind `Other` (non-tunable).

### 4. Tests (`tests/talkback_template.rs`)
Add a `BoolParamArgs` struct with a `bool` field and assert `render_template_toml`
round-trips via `toml::from_str` with a `Bool` param (`type = "Bool"`), the
template contains `--use-dropout {use_dropout}`, and `render_template_command`
renders the placeholder (not a bare flag). Add a skipped-bool field
(`#[param(skip = true)]`) and assert it is **excluded** from the space while the
CLI still parses `--skip-me` / `--skip-me false` (checked via `--help` output).
