# Plan: Unified `init()` entry point + standalone no-op — make argtuner-talkback a clap adapter

## Vision
The clap struct becomes the single source of truth for an algorithm's parameter
interface. Declare params once → get (a) a standalone production CLI and (b)
zero-touch argtuner compatibility. Unified entry: `argtuner_talkback::init::<P>()`
(re-exported as `argtuner::init`), a `Talkback` whose `emit_*` methods silently
no-op when the binary runs standalone (not under argtuner).

## Changes

### 1. `crates/common/src/lib.rs` — shared marker constant
Add near `RESULT_PREFIX`:
```rust
/// Env var the tuner always exports to trial subprocesses; the binding checks
/// it to detect "running under argtuner" and suppresses stdout emission when
/// absent (standalone runs stay clean).
pub const TUNING_MARKER_ENV: &str = "ARGTUNER_TUNING";
```

### 2. `src/trial/mod.rs` — always export the marker
In `render_trial_command_with_overrides`, OUTSIDE the
`if inject_trial_placeholders` block, add to the `env` map:
```rust
env.insert(argtuner_common::TUNING_MARKER_ENV.to_string(), "1".to_string());
```
(`rendered.env` is passed to the subprocess via `CommandRunner`, so every trial
child sees `ARGTUNER_TUNING=1`, even when `inject_trial_placeholders = false`.)
Update the existing `render_uses_trial_id_for_trial_dir` unit test to assert the
marker is present.

### 3. `bindings/rust/src/lib.rs` — unified init + gating
- Add `active: bool` to `Talkback`. `Talkback::init()` sets it from
  `std::env::var_os(argtuner_common::TUNING_MARKER_ENV).is_some()` and only
  emits the version handshake when active.
- Instance `emit_event` / `emit_result` / `emit_epoch_end` / `emit_step_end`:
  `if !self.active { return Ok(()); }` (silent no-op when standalone). Add
  `pub fn active(&self) -> bool`.
- Add the canonical unified entry (thin wrapper; keep `init_with_args` as the
  legacy alias, update docs to prefer `init`):
  ```rust
  pub fn init<T: clap::Parser + clap::CommandFactory>() -> (Talkback, T) {
      init_with_args::<T>()
  }
  ```
- Free functions (`emit_event` etc.) stay un-gated (low-level escape hatch).
- Doc-comments updated: struct-based emission required (metric key comes from
  the named field); scalars NOT auto-wrapped.

### 4. `src/lib.rs` (argtuner) — re-export from the root
```rust
pub use argtuner_talkback::init;
pub use argtuner_talkback::Talkback;
pub use argtuner_talkback_derive::talkback_args;
```
(argtuner already depends on both crates — `argtuner-talkback` with the `clap`
feature — so `argtuner::init::<P>()` is available in every build, incl.
`--no-default-features`.)

### 5. Examples — migrate to `init`
Update `examples/linear_regression/main.rs`, `examples/loss_pattern_generator/main.rs`,
`examples/interactive_probe/main.rs` from `init_with_args` → `init` (keep direct
`argtuner_talkback::` paths — the honest story for consumers who only want the
binding).

### 6. Docs
- `bindings/rust/README.md`: reframe around the vision — "declare your
  algorithm's parameter interface once; get a production CLI + zero-touch
  argtuner compatibility". Lead with `argtuner_talkback::init::<P>()`; document
  the standalone no-op (marker env), struct-required emission, and that it's
  re-exported as `argtuner::init` / `argtuner::talkback_args`.
- Main `README.md` `### The argtuner-talkback Rust Binding` blurb: mention the
  unified `init` entry and the re-export.

## Verification
1. `cargo test --workspace --all-features --lib --tests` — full suite green
   (incl. updated trial env unit test and examples via `--examples`).
2. `cargo build --no-default-features` — argtuner lib still compiles with the
   re-export (talkback is not feature-gated).
3. `cargo run -p argtuner --example linear_regression -- --lr 0.01 --steps 20`
   — standalone run: NO `::ARGTUNER::` output (marker absent → no-op).
4. `cargo run -p argtuner -- run examples/linear_regression --dry-run` — under
   argtuner: emission works (marker present).
5. `cargo clippy --all-features --all-targets` — clean.
