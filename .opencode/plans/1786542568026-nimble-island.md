# Plan: Replace hardcoded line endings with the `line-ending` crate (full workspace audit)

## Goal
Remove hardcoded `\n`/`\r\n` from production code and use the `line-ending`
crate everywhere line endings are emitted or normalized, so the codebase is
deliberately cross-platform. `line-ending` must move from `[dev-dependencies]`
to `[dependencies]` (lib modules use it now).

The crate (`line-ending 1.5.1`) exposes `LineEnding::{LF, CRLF, CR}` with
`as_str()`, `as_char()`, `normalize(s)`, `from_current_platform()`, `join()`,
etc.

## Cargo.toml
Add `line-ending.workspace = true` to `[dependencies]` (keep the existing
`[dev-dependencies]` entry too — harmless duplication is fine, or drop the dev
entry since it's now a regular dep; keep both to minimize churn).

## Conversions (production code only)

### A. Input normalization → `LineEnding::normalize`
- `src/test_support.rs:74` — `.replace("\r\n", "\n")` → `LineEnding::normalize(after_fence)`.
  (More correct than today: also normalizes lone `\r`; restores what the original
  `tests/protocol_schema.rs` used before this helper moved into the lib.)

### B. LF-mandated formats → `LineEnding::LF` (byte-identical, documents intent)
These formats must stay LF on every platform; the crate makes that deliberate:
- `src/inspect.rs` (lines 25, 26, 27, 29, 57, 67, 71, 91) — output framing; the
  README `<!-- config.inspect.output -->` block is asserted byte-exact, so LF is
  required. Use a local `let lf = LineEnding::LF.as_str();` and `{lf}` in the
  format strings.
- `src/trial/store.rs:108,134` — step-publisher line-framed socket messages:
  `line.push('\n')` → `line.push(LineEnding::LF.as_char())`. Resolves the
  existing `// TODO: Use line-ending crate` at line 134.
- `src/discover.rs:110,127` — `.gitignore`/`.ignore` contents (git spec wants
  LF) → `LineEnding::LF.as_str()` joined in the literal strings.
- `src/lock.rs:39` — lockfile metadata (parsed with `.lines()`, LF canonical).
- `src/command/objective.rs:27` — log-tail `lines[start..].join("\n")` →
  `.join(LineEnding::LF.as_str())` (input already LF-normalized by `.lines()`).

### C. Terminal/display output → `LineEnding::from_current_platform()`
Leading-newline banners and user-facing messages now use the platform ending:
- `src/analysis/mod.rs:150,155,182` — `println!`/`eprintln!` report banners.
- `src/checkpoint.rs:123` — shutdown banner.
- `src/command/objective.rs:238,412,449` — per-trial banners.
- `src/trial/store.rs:347` — "refusing to resume" message.

(No test asserts these byte-for-byte — verified by grep — so platform endings
are safe.)

## Explicitly NOT converted (documented rationale)
- `src/cli/mod.rs:17` — clap `help_template` attribute: a compile-time literal;
  `LineEnding::LF.as_str()` is not `const fn`, so it can't be used in the
  attribute.
- `examples/interactive_probe/main.rs:272` — `'\n'` there is URL
  percent-encoding (`%0A`), not a line ending.
- Test fixtures and assert-message strings (`tests/*.rs`, `src/trial/store.rs:925`,
  `src/command/subprocess/runner.rs:471`, `crates/common/src/lib.rs:102`):
  exact-byte inputs to parsers; converting is noise with no correctness value.
