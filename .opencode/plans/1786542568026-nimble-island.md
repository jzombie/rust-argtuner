# Plan: Implement Epics B, A, C — process hygiene, conditional params, multi-objective

Executed in order **B → A → C**, each a complete verifiable phase. (The earlier
Items 1–3 — README Bool docs, Bool tests, lightweight `--no-default-features` —
are already implemented and remain.)

---

## Phase 1 — Epic B: Process-tree hygiene & per-trial timeouts

**Goal:** no orphaned sub-child processes on trial abort/timeout; config-driven
per-trial timeout.

### B1. Process groups
- Add `command-group` as a workspace + argtuner dep for the **piped** path
  (`command-group` extends `std::process::Command`/`Child`).
- The **PTY** path uses `portable_pty::CommandBuilder` (returns a
  `portable_pty::Child` trait object, **not** `std::process::Child`, so
  `command-group` does not apply): spawn with
  `CommandBuilder::process_group(true)` (Unix), then kill the group natively —
  `process_id()` returns `Option<u32>`, so unwrap before the signal:
  ```rust
  if let Some(pid) = child.process_id() {
      // reaped-guard checked before this
      unsafe { libc::kill(-(pid as i32), libc::SIGKILL); }
  }
  ```
  Windows never uses the PTY path (the runner is piped there), so Job Objects via
  `command-group` cover Windows; if a Windows PTY path is ever added, attach the
  PID to a Job Object before spawn.
- `src/command/subprocess/runner.rs`:
  - Piped path (`run_piped`): `command_group::GroupCommand` → `GroupChild`, kill
    the group as a unit.
  - PTY path (non-Windows): keep the pgid (child pid) and `libc::kill(-pgid,
    SIGKILL)` on teardown.
  - Runner accepts `timeout: Option<Duration>` + a kill/cancel signal.

### B2. Per-trial timeout + cancel
- Config: add `trial_timeout_s: Option<u64>` to `[scheduler]` (`SchedulerConfig`),
  0/absent = none.
- Runner: when a timeout is set, a watchdog kills the process group after the
  deadline; the trial is marked `error` with a "timed out" reason.
- Cancel: the existing `stop_flag` (Ctrl-C / TUI quit) now also kills the active
  trial's process group, not just waits.
- **Group-kill is synchronized against the reap:** a shared `AtomicBool`/
  `Arc<Mutex<Option<Child>>>` marks the child reaped as soon as the wait loop
  collects it; watchdog/cancel paths check it **before** calling
  `kill(-pgid, SIGKILL)` and skip if already reaped — preventing a recycled PGID
  from being killed.
- `src/command/objective.rs` wires timeout + group-kill into trial execution;
  `src/tuner/mod.rs` passes the timeout through.

### B3. Tests + verification
- Unit: piped spawn starts a grandchild (e.g. `sh -c "sleep 100 & sleep 100"`);
  killing the group reaps both children (verify no survivors via `ps`).
- Timeout: a mock that sleeps beyond the timeout → trial errors with "timed out",
  child reaped.
- `cargo test --workspace --all-features`; clippy; CI cross-platform (Unix +
  Windows) since process-group semantics are OS-specific.

## Phase 2 — Epic A: Conditional hyperparameters

**Goal:** a param is active only when its parent sampled an allowed value; its
argument is **omitted** from the rendered command when inactive.

### A1. Search-space AST (`src/search_space/mod.rs`, `src/sdk.rs`, derive)
- `ParamSpec` (and `ParamHint`) gain:
  ```rust
  parent: Option<String>,
  parent_values: Option<Vec<String>>,
  ```
  Serialized as `parent = "optimizer"`, `parent_values = ["sgdt"]` in
  `[[space.params]]`; `ParamSpecPre`/`TaggedParamSpec` + `From` updated; the
  derive parses `#[param(parent = "optimizer", parent_values = ["sgdt"])]`.
- DAG validation in `validate_specs`:
  - parent must exist; no cycles; parent must yield a finite set of string
    values — `Choice`, **`Bool`** (`parent_values` = `["true"]`/`["false"]`), or
    a fixed string-valued param.
  - `parent` and `parent_values` are paired: both set or both `None`;
    `parent_values` must be non-empty.
  - `parent_values` domain containment: every value must be a permitted value of
    the parent (`parent.choices` for `Choice`, or `["true", "false"]` for
    `Bool`); otherwise the child is permanently unreachable and the config is
    rejected.
  - conditional params (with a `parent`) must be bound to a named `--flag`
    (positional placeholders are rejected — there's no flag token to strip).

### A2. Conditional sampling + rendering
- `SearchSpace::values_from_unit`/`fields_from_unit` evaluate in dependency
  order and **omit** inactive params (no value, no `hp.*` field).
- `src/command/template.rs` / `src/trial/mod.rs` rendering: after filling
  placeholders, strip each inactive param's flag segment from the command. The
  token-aware removal matches both `--flag {value}` (two shell tokens) and
  `--flag={value}` (one unified token), respecting shell quoting. Conditional
  params are guaranteed flag-bound by `validate_specs` (positionals rejected), so
  there is always a flag token to strip. Evaluate conditions against the sampled
  parent value.
- Random sampler's `DiscreteConfigPool` enumerates only parent-valid
  combinations (duplicate detection stays correct).

### A3. Inspect + tests
- `argtuner inspect` shows the dependency (e.g.
  `{momentum}: … parent optimizer ∈ [sgdt]`).
- Tests: config serialization round-trip; a two-level conditional (grandchild)
  validates; inactive arg is absent from the rendered command; active arg is
  present; discrete pool skips invalid combos; `hp.*`/space omit inactive params.

## Phase 3 — Epic C: Multi-objective optimization

**Goal:** optimize several objectives against a Pareto frontier, not a single
scalar.

### C1. Config + protocol
- `[project]` gains objectives, with an explicit **primary** objective for
  early-stopping schedulers:
  ```toml
  [[project.objectives]]
  name = "loss"
  goal = "minimize"
  primary = true

  [[project.objectives]]
  name = "latency_ms"
  goal = "minimize"
  ```
  Validation: when an early-stopping scheduler (`SuccessiveHalving`) is enabled,
  exactly one objective must be `primary = true`. Backward-compatible: when
  objectives are absent, `metric_key` + `goal` drive a single-objective run.
  `ProjectSettings`/`ProjectConfig` gain `objectives: Vec<Objective>`.
- Protocol unchanged on the wire (`metric.*` fields already carry every metric);
  storage unchanged (`fields_json`).

### C2. Pareto engine + sampler (`src/sampler/pareto.rs`, `src/sampler/`)
- `src/sampler/pareto.rs`: non-dominated sorting (Deb's fast sort) + crowding
  distance; `dominates`, `pareto_front(records) -> front`.
- **Objective-direction normalization:** objectives may mix `minimize` and
  `maximize` goals, but Deb's sort assumes one unified (minimization) space.
  Before any dominance comparison, normalize each score vector by negating
  `maximize` objectives (`maximize → -score`); crowding distance is computed on
  the normalized vectors too. Normalization is **internal only** — CLI, TUI, and
  database persistence (`fields_json`) retain and present raw, un-negated
  metric values.
- Sampler trait: sample a config, evaluate all objectives, update the
  non-dominated front; a new `ParetoSampler` (random/NSGA-II-lite) maintains the
  front with crowding-distance diversity. Single-objective samplers (random/PSO)
  unchanged.

### C3. Scheduler + reporting + checkpointing
- `TrialScheduler::record_result(token, score: Option<f64>)` becomes
  `record_result(token, scores: Vec<f64>)`.
- **Metric-cardinality validation at ingestion** (`src/command/objective.rs`):
  the extracted score vector must have exactly `objectives.len()` entries. If any
  declared objective metric is missing from the trial payload, the trial is
  rejected and marked `error` ("missing objective metric: <name>") — never passed
  through as a short vector, so no `scores[primary_index]` out-of-bounds.
- `SuccessiveHalvingScheduler` (and any rung-truncating scheduler) uses the
  **primary objective's index** for scalar truncation at each rung — a
  deterministic `primary` metric must be configured when such a scheduler is
  enabled (see C1). The full score vector still flows to the `ParetoSampler`.
  `FixedScheduler` accepts the vector as-is.
- CLI/TUI: replace single "best trial" with a Pareto-frontier table (non-dominated
  trials + their objective vectors); `argtuner inspect` lists objectives.
- Checkpointing: persist the non-dominated front (ids + scores), not one best.

### C4. Tests
- `pareto.rs` unit tests: dominance, Deb sort on a known set, crowding distance.
- End-to-end: a 2-objective mock emits `loss` + `latency_ms`; assert the front
  contains the true non-dominated set and that dominated trials are excluded.

## Addendum — Epic B closing gaps (agreed after implementation review)

Epic B was implemented per the plan's intent with two benign mechanism
deviations (recorded for accuracy, no rework needed):
- PTY group creation relies on portable-pty's built-in `setsid()` (child is a
  session/process-group leader) instead of `CommandBuilder::process_group(true)`,
  which does not exist in the portable-pty API; `kill(-pgid, SIGKILL)` behaves
  exactly as planned.
- Reap-sync uses a single main-thread poll loop (`wait_with_timeout`) that kills
  only while `try_wait` reports the child alive, instead of a separate watchdog
  thread + shared reaped-flag. Same invariant (never signal a recycled PGID),
  no cross-thread race.
- `trial_timeout_s` is `u64` default `0` (not `Option<u64>`); 0/absent = none.

Two gaps remain to close:

### G1. Cross-platform self-invoking subprocess tests (replaces the shell-based tests)

The `sh`/`sleep`/`echo`-based tests are not Windows-compatible (`sh`, `sleep`
don't exist on Windows). Replace them with a single self-invoking pattern: the
test binary re-executes **itself** (`std::env::current_exe()`) filtered to one
helper test via the libtest filter arg, with an env var selecting the role.

**`src/test_support.rs` additions** (module is already `cli`-gated):
- Consts: `SELF_ROLE_ENV = "ARGTUNER_SELF_ROLE"`,
  `SELF_PID_FILE_ENV = "ARGTUNER_SELF_PID_FILE"`,
  `SELF_HEARTBEAT_ENV = "ARGTUNER_SELF_HEARTBEAT"`, and private
  `SELF_TEST_FILTER = "test_support::self_invoking_helper"`.
- `pub fn self_invoking_command() -> String`: builds
  `{quoted_exe} --exact {SELF_TEST_FILTER}` with **platform-specific quoting**:
  - `#[cfg(not(windows))]`: `shell_words::quote(&exe.to_string_lossy())`
    (POSIX single-quoting).
  - `#[cfg(windows)]`: double-quoted `"{exe}"` — `split_command_windows`
    parses `"`-delimited tokens per Windows rules; POSIX single-quoting is NOT
    understood by the Windows tokenizer and would leave literal `'` in the exe
    path (`NotFound` at spawn).
  - The runner splits this with `shell_words` (Unix) / `split_command_windows`
    (Win); quoting the path handles spaces (`/Volumes/2TB Storage Vault/...`).
  - **`--exact` is mandatory:** without it libtest treats the filter as a loose
    substring and could run multiple matching tests; with `--exact` +
    `test_support::self_invoking_helper` exactly one test runs.
- `#[test] pub fn self_invoking_helper()` — role dispatcher reading
  `SELF_ROLE_ENV`:
  - `noop`: returns immediately (harness exits 0).
  - `sleepy`: sleeps 100s (timeout / cancellation target).
  - `grandchild`: writes `std::process::id()` to `SELF_PID_FILE_ENV`, then loops
    writing a monotonically increasing counter to `SELF_HEARTBEAT_ENV` every
    100ms (the liveness signal below).
  - `child`: spawns `current_exe()` with args `["--exact", SELF_TEST_FILTER]`
    and env `SELF_ROLE_ENV=grandchild` + the propagated `SELF_PID_FILE_ENV` +
    `SELF_HEARTBEAT_ENV`, then `wait()`s.
  - unset: no-op pass (normal `cargo test` run of the helper).
  - **Correctness linchpin:** every self-spawn passes `--exact
    {SELF_TEST_FILTER}`, so the subprocess harness runs exactly this one test —
    never the whole suite (prevents recursive test explosion). A mismatch fails
    loudly (child exits 0 → driver's `timed_out`/exit-code assertions fail), not
    silently.
- **Liveness = heartbeat, not `kill(pid, 0)`.** On Unix `kill(pid, 0)` returns
  success for **zombies** (terminated but unreaped), so an `is_process_alive`
  probe reports a zombie as alive and flakes on CI. Instead a running grandchild
  advances its heartbeat file; a dead or zombie grandchild cannot. Add
  `pub fn assert_no_longer_running(pid: u32, heartbeat_file: &Path,
  grace: Duration) -> ()`: reads the heartbeat size, sleeps `grace` (≥ 2
  heartbeat intervals), re-reads; asserts unchanged (with a message naming the
  pid). Cross-platform, no `/proc`, no sysctl, no Windows handle API.
- No new dependencies and **no `Cargo.toml` change** (the earlier
  `Win32_System_Threading` idea is dropped — no Windows handle API is used).

**`src/command/subprocess/runner.rs` tests — rewrite all four subprocess tests**
(currently `echo` / `sleep 30` / `sh -c`):
- `run_piped_completes_without_options`: role `noop`; assert exit 0,
  `!timed_out`.
- `run_times_out_and_kills_process_group`: role `sleepy`, `timeout` = 2s; assert
  `timed_out`, exit != 0, elapsed < 15s.
- `run_stop_flag_kills_process_group_without_timeout`: role `sleepy`, stop flag
  flips after 300ms; assert `!timed_out`, exit != 0.
- `run_timeout_kills_grandchild_processes`: role `child` +
  `SELF_PID_FILE_ENV`/`SELF_HEARTBEAT_ENV` = two `tempfile::tempdir()` paths,
  `timeout` = 2s; assert `timed_out`; parse the grandchild pid (defensive
  diagnostic if the pid file is missing — the grandchild writes it on boot,
  well before the 2s deadline); then
  `assert_no_longer_running(pid, &heartbeat, 600ms)` — proves the group kill
  stopped the whole tree.
- All pass the role/heartbeat paths through the runner's `envs: BTreeMap`
  (never the process env) → no cross-test races.

**`src/command/objective.rs` — convert
`objective_times_out_long_command_and_marks_error`** (currently
`CommandTemplate::new("sleep 30")`, Unix-only):
- Template = `self_invoking_command()`. Inject the role without the process env:
  `TrialOverrides { env: {SELF_ROLE_ENV: "sleepy"}, ..Default::default() }` via
  `eval_with_overrides(&[], &overrides)` — `render_trial_command_with_overrides`
  already copies `overrides.env` into `rendered.env` (src/trial/mod.rs:66), which
  the runner sets on the child. Assertions unchanged (`timed out` error + trial
  marked `error`).

**Deletion:** remove the current shell-based `run_timeout_kills_grandchild_processes`.
