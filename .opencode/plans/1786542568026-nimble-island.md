# Plan: Redesign `argtuner inspect` output (drop TOML round-trip, add execution summary)

## Goal
`argtuner inspect` currently dumps the config back as normalized TOML (mental
overhead — the user just read the toml). Redesign it to synthesize *how argtuner
interprets the run*: template, placeholder resolution, and a one-glance
execution summary.

New output shape (from `examples/config_showcase`):
```text
project: examples/config_showcase

template:
  cargo run -p argtuner --example loss_pattern_generator -- --pattern noisy --steps {steps} --noise {noise} --metric-key val_loss --checkpoint-dir {trial_dir} --epoch-time 1

placeholders:
  {noise}:     space param Float in [0.01, 0.5], log-scale
  {steps}:     space param Int in [20, 300], step 20; scheduler budget placeholder (overridden per rung)
  {trial_dir}: reserved: per-trial artifact directory (auto-injected)

execution:
  metric:    val_loss (minimize)
  sampler:   random
  scheduler: successive_halving (30 trials)
```

## Changes

### 1. `src/inspect.rs` — rewrite `render_inspect`
- **Remove** the normalized TOML round-trip (`normalized_config_toml` helper and
  the `toml::Value::try_from` / `toml::to_string_pretty` call) entirely.
- **Keep** the `project:` header (forward-slash-normalized root).
- **template:** print the template flattened to a single line:
  `template.lines()` → `.trim()` → `.trim_end_matches('\\')` (strip the
  `\` line-continuations) → drop empties → `join(" ")`, indented 2 spaces.
- **placeholders:** keep the existing per-token resolution but right-align the
  `{name}:` labels to the longest token (width = longest name + 2, then a space)
  so the descriptions line up. Reserved `trial_id`/`trial_dir` and the
  successive-halving budget note unchanged.
- **execution:** new `execution_summary(&UnifiedConfig)` block:
  - `metric: <metric_key> (<minimize|maximize>)` — from `project.metric_key` +
    `project.goal` (`Goal::Min`→"minimize", `Goal::Max`→"maximize")
  - `sampler: <random|pso>` — `sampler.kind`
  - `scheduler: <fixed|successive_halving> (<n_trials> trials)` — `scheduler.kind`
    + `scheduler.n_trials`
  - Labels right-aligned via `format!("  {label:<10} {value}")` to match the
    mock's `metric:`/`sampler:`/`scheduler:` columns.
- Imports: add `Goal`, `Sampler` from `crate::project` (already re-exported);
  keep `crate::scheduler::Scheduler`. `toml` no longer referenced.

### 2. `Cargo.toml` — revert toml `preserve_order`
The `preserve_order` feature was added solely for the inspect round-trip.
Revert `toml = { version = "1.1", features = ["preserve_order"] }` →
`toml = "1.1"`. Nothing else used it (`save_unified_config` serializes structs
directly, so field order is unaffected).

### 3. `README.md` — sync the inspect echo
- Regenerate the `<!-- config.inspect.output -->` text block with the new output
  (run the binary, paste verbatim).
- Update the prose above it ("To see exactly what argtuner deserializes…")
  to describe the new synthesis (template + placeholder resolution + execution
  summary) instead of "parsed config structs (defaults applied)".
- Update the config-layout Notes bullet that mentions `argtuner inspect` printing
  "the deserialized structs (defaults applied, e.g. pruner = none)" to instead
  say it shows how argtuner interprets the run (template, placeholders,
  execution summary).
