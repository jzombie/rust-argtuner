`src/main.rs` a thin wrapper. It does **not** compile yet (4 errors) and is **not**
feature-gated yet. This plan completes both.

Current state:

- `src/cli/mod.rs` → `mod tui;` + `Cli`/`Commands` + `fn main()` (renamed from the old entry) + `cli_tests` module, with broken `argtuner::...` internal paths

## Changes

### 1. Move the TUI under the cli module
`git mv src/tui src/cli/tui`
The Watch TUI is cli-only; nesting it keeps the public lib surface clean (no `pub mod tui`).
The `#[cfg(test)] mod key_tests` inside `tui/mod.rs` travels with it unchanged.

### 2. Fix `src/cli/tui/mod.rs` internal imports (lines 6–8)
`argtuner::` → `crate::`:
- `use argtuner::constants::{FIELD_METRIC, FIELD_SCORE, HP_PREFIX};` → `use crate::constants::...;`
- `use argtuner::project::Project;` → `use crate::project::Project;`
- `use argtuner::trial::store::StepSubscriber;` → `use crate::trial::store::StepSubscriber;`

(No other `argtuner::` references exist in tui — verified by grep.)

### 3. `src/cli/mod.rs`: entry point + self-paths + visibility
- Rename `fn main()` → `pub fn run()` (body unchanged; keeps `std::process::exit(1)` error semantics — user chose `cli::run()` + exposed types over a `Result`-returning API).
- Fix self-references (lines 82, 122, 155): `argtuner::` → `crate::`
  - `crate::tuner::RunOptions`
  - `crate::find_projects`
  - `crate::scheduler::build_plan`
- Make types public for library reuse:
  - `pub struct Cli` with `pub command: Commands` (struct fields require explicit `pub`)
  - `pub enum Commands` — variants and their fields inherit the enum's visibility automatically, so NO `pub` on the enum or on variant fields (e.g. `Run { pub path: ... }` is a compile error). Just declare the enum `pub`.
- Tests (`cli_tests`): unchanged; they already use `super::Cli`/`super::Commands`.

### 4. Feature gate behind `cli` (default on)
**`Cargo.toml`:**
```toml
[features]
default = ["cli"]
cli = ["dep:clap", "dep:crossterm", "dep:hostname", "dep:ratatui",
       "dep:term-wm", "dep:term-wm-console", "dep:term-wm-core",
       "dep:term-wm-render", "dep:term-wm-ui-facade"]

[[bin]]
name = "argtuner"
path = "src/main.rs"
required-features = ["cli"]
```
- Mark the 9 deps above `optional = true` (clap → `{ workspace = true, features = ["derive"], optional = true }`; the rest → `{ workspace = true, optional = true }`).
- `required-features` makes `--no-default-features` builds skip the binary cleanly (main.rs calls `argtuner::cli::run()`, which won't exist without the feature). CI always builds `--all-features`, and `CARGO_BIN_EXE_argtuner` tests still work.

**`src/lib.rs`:** `pub mod cli;` → `#[cfg(feature = "cli")] pub mod cli;`
(tui is private inside cli, so nothing else to gate; its TUI-only deps — ratatui, hostname, term-wm*, crossterm — are exactly the optional set above.)

Note: `crossterm` and `term-wm-render` are declared-but-unreferenced direct deps today; making them optional+gated is behaviorally identical for CI (`cargo udeps --all-features` enables them), so no udeps regression.
