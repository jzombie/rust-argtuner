# Production-readiness gaps for PSO checkpoint resume + stale-Running sweep

## CRITICAL CONSTRAINT: Sweep NEVER touches non-Running trials

The sweep **must** only affect trials with `status == "running"` at the moment
the sweep runs. It must **never** modify any trial that has status `"ok"` or
`"error"`, regardless of its role in SHA parent chains or any other relationship.

The existing `sweep_ignores_non_running` test enforces this. The new
`sweep_does_not_touch_parent_trial` test (item 1d below) explicitly verifies
that a completed `Ok` trial (which is a parent in an SHA chain) is completely
untouched by the sweep.

---

## 1. Sweep must reset stale Running trials for re-execution (HIGH)

**Problem:** Currently `sweep_stale_running_trials` marks stale `Running` trials
as `Error`. The user wants them **reset** (not errored) so the sampler re-issues
`eval` with the same `trial_id` and the trial restarts cleanly.

**Files:** `src/checkpoint.rs`, `src/trial/store.rs`, `src/trial/db.rs`

**Implementation:**

### 1a. Add `reset_trial` method to `TrialStore` / `TrialDb`

A new method that:
- Clears all fields from the trial record (sets `fields_json` to `{}`)
- Sets status back to `Running`
- Clears `elapsed_ms` and `error`
- Does NOT change the `trial_id`

This is an UPDATE (upsert), not a delete. The record still exists in SQLite,
but the fields are cleared.

`TrialStore::reset_trial(trial_id)` → `TrialDb::reset_trial(trial_id)`

### 1b. No change needed in eval code

`eval_with_overrides_internal` already handles this correctly:
- `load_fields(trial_id)` returns `Some(empty_map)` after reset
- The "existing" path is taken → `merge_running_fields(empty_map, rendered)` renders the new fields
- The duplicate check is skipped (guarded by `existing_fields.is_some()`)

The re-evaluation runs cleanly with the same `trial_id`.

### 1c. Replace `sweep_stale_running_trials` body

Instead of marking as `Error`, call `store.reset_trial(trial_id)` and delete
the artifact dir. Return count of swept trials.

### 1d. Tests

**Update existing tests:**
- `sweep_removes_artifact_dir_and_marks_error` → rename to
  `sweep_resets_running_trial`; verify status is still `Running` after sweep,
  artifact dir gone, fields empty, elapsed_ms=0, error=None
- `sweep_handles_missing_dir` → same; verify no crash when dir already gone
- `sweep_ignores_non_running` → unchanged
- `sweep_does_not_regress_duplicate_check` → verify after reset,
  `find_duplicate_config` still skips the trial (Running → skipped)

**New tests:**
- `sweep_allows_re_eval_with_same_trial_id` — create stale Running trial,
  sweep it, then call `objective.eval_with_overrides_retryable(..., Some(id))`
  and verify it succeeds (not duplicate-blocked)
- `sweep_does_not_touch_parent_trial` — create an `Ok` trial with
  `config_id=0` (simulating an SHA parent), create a stale `Running` trial
  with `config_id=1`, run sweep, then verify:
  - The `Ok` trial is completely unchanged (fields, status, elapsed_ms, error)
  - `find_last_trial_for_config(0)` still returns the `Ok` trial's `trial_id`
  - Only the `Running` trial was reset

## 6. Cache misses for swept trials with no score (LOW)

After sweep, stale trials are reset to `Running` with cleared fields, so there
is no `FIELD_SCORE`. `build_trial_result_cache` correctly skips them. When PSO
revisits that HP config, it's a cache miss and the command runs from scratch.

**Assessment:** This is correct — the command was never completed, so there is
nothing to cache. No code change needed.

## 7. CSV-only reads (NOT a risk — included for clarity)

`trials.csv` is purely write-only (a human-readable snapshot). The SQLite DB is
the authoritative source for all reads. No conflict or edge case here.

**Assessment:** Confirmed by code audit — `load_rows()`, `load_fields()`, and
all control-flow methods read from SQLite only. No code change needed.
