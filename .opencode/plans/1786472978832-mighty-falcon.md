# Plan: Echo the protocol schema in the README and assert it

## Goal

Embed the canonical `protocol.schema.json` directly in the root README's
protocol section so readers see the whole contract inline, and add a test that
asserts the README copy matches the generated schema so it can never drift.

The schema-generation machinery already exists from the prior change
(`argtuner_common::protocol_schema_string()`, the committed asset
`crates/common/assets/protocol.schema.json`, and the drift test
`committed_schema_is_current` in `crates/common/src/protocol.rs`). This task
only adds a second echo (in README) and an assertion that pins it.

## Changes

### 1. `README.md` — embed the schema in the protocol section (collapsible)

Insert, between the "self-describing" paragraph (ends ~line 65, right after the
`schematic` sentence about `x-argtuner`) and the "For example:" block (line 67):

```markdown
The canonical schema is echoed below, collapsed to keep this doc skimmable;
`tests/protocol_schema.rs` asserts it is byte-identical to the generated
schema, so it cannot go stale:

<!-- protocol.schema.json -->
<details>
<summary>Canonical protocol JSON schema</summary>

```json
{ …contents of crates/common/assets/protocol.schema.json verbatim… }
```

</details>
```

- `<details>`/`<summary>` keeps the 76-line JSON block out of the top-level
  reading flow while remaining inline and extractable for the test.
- The HTML comment `<!-- protocol.schema.json -->` above the `<details>` is the
  machine marker the test scans for (the README currently has **zero**
  ` ```json ` fences, but the marker keeps extraction unambiguous even if later
  json examples are added).
- Contents = the current committed asset, byte-for-byte.

### 2. `tests/protocol_schema.rs` — add the assertion

Add two items:

- A hardened helper that extracts the block strictly:
  1. locate `<!-- protocol.schema.json -->`;
  2. from there, find the next ` ```json ` fence opener;
  3. take everything from just after that opener up to the next closing ` ``` `
     fence (must immediately follow the block — no nested fences possible for
     JSON, so first closing fence is correct);
  4. return the slice `.trim()`ed.
  Panic with a clear message if the marker or either fence is missing.
- A test `readme_echoes_current_schema`:
  - `let readme = include_str!("../README.md");`
  - extract the echoed block;
  - `assert_eq!(echoed.trim(), SCHEMA.trim())` where `SCHEMA` is the existing
    `include_str!("../crates/common/assets/protocol.schema.json")` const —
    tying the README copy to the committed artifact, which is itself already
    drift-checked against the runtime-generated schema. Trimming both sides
    absorbs the trailing newline the shell adds on redirect and any incidental
    fence-adjacent whitespace.
  - Failure message tells the exact regenerate-and-paste steps:
    `cargo run -p argtuner --bin print_protocol_schema > crates/common/assets/protocol.schema.json`
    then paste that file's contents into the README block.

No changes to `crates/common`, bindings, or the parser — the shared types and
generation already live in `crates/common/src/protocol.rs`.
