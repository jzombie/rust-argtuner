# Plan: Get `cargo publish --workspace` green

## Conceptual clarifications (the user's questions)

- **You do NOT need to publish deps to crates.io first for `--workspace`.** A single
  `cargo publish --workspace` packages and verifies *all* members together against the
  locally-packaged crates (`target/package/`). The earlier "publish the chain first" guidance
  applies only to publishing a *single* crate (`-p argtuner`) that depends on unpublished
  members — it does not apply to `--workspace`.
- **The internal crates are not private.** `argtuner-common`, `argtuner-talkback`, and
  `argtuner-talkback-derive` are publishable (`publish = true`, inherited). Only
  `argtuner-mock-bin` is intentionally `publish = false` (test-only). `cargo publish
  --workspace` skips it.

## Root causes of the current failures

1. **`FORCE_PIPES_ENV` not found during verify** — stale `target/package/` snapshots from
   earlier `cargo package`/`publish` runs predate the constant. The working tree and the
   current snapshot both contain it now, but the old tarball/dir in `target/package/` was
   reused for verification. Fix: clear `target/package/` so every member is freshly packaged.
2. **`manifest has no description`** — crates.io rejects uploads without `description`.
   No workspace member has one.
