# Plan: Replace the mock-bin timer (`hold_stdout_open`) with test pipe mode

## Problem

`hold_stdout_open()` makes mock emit binaries `sleep(50ms)` before exit so a PTY parent can
drain lines before the macOS kernel destroys the PTY buffer on slave close. Blind timer →
data-loss risk under load + per-trial latency. Fix: run test subprocesses over **pipes**
(guaranteed deliver-before-EOF), via a test-only Unix pipe toggle. No timer, no nightly.

## Injection model (per review — no env mutation, no UB)

`CommandRunner::run` is called **only** from the objective (`objective.rs:258`); no test calls
it directly; most tests drive subprocesses in-process (`Tuner::run`, objective, PSO,
checkpoint); only `binding_version_mismatch` spawns `argtuner` externally. So:

- **In-process tests** need a safe, non-env signal → a `static AtomicBool` test hook
  (UB-free; does not mutate the process environment).
- **External spawn** (`binding_version_mismatch`) → `Command::new(..).env(FORCE_PIPES_ENV, "1")`.

## Changes

### 1. `crates/common/src/lib.rs`

```rust
/// When present in the child envs or the argtuner process environment,
/// `CommandRunner` uses piped stdio instead of a PTY (test-only).
pub const FORCE_PIPES_ENV: &str = "ARGTUNER_FORCE_PIPES";
```

### 2. `src/command/subprocess/runner.rs`

- Extract the current Windows `run()` body into a shared
  `fn run_piped(command, envs) -> Result<CommandOutput, String>`; Windows `run()` calls it.
- Add a safe global test hook:
  ```rust
  static FORCE_PIPES: AtomicBool = AtomicBool::new(false);
  impl CommandRunner {
      /// Test-only: force all subprocesses in this process to use pipes.
      #[doc(hidden)]
      pub fn force_pipes_for_tests() { FORCE_PIPES.store(true, Ordering::Relaxed); }
  }
  ```
- Unix `run()`:
  ```rust
  if FORCE_PIPES.load(Ordering::Relaxed)
      || envs.contains_key(argtuner_common::FORCE_PIPES_ENV)
      || std::env::var_os(argtuner_common::FORCE_PIPES_ENV).is_some()
  {
      return run_piped(command, envs);
  }
  ```
  Production `argtuner run` is unaffected (no flag set). The `var_os` arm covers the external
  `argtuner` spawn in `binding_version_mismatch` (its `.env(...)` lands in the child's env).

### 3. `src/test_support.rs`

- At the top of `bin_path`/`bin_command`, call
  `crate::command::subprocess::CommandRunner::force_pipes_for_tests();` (idempotent — no
  `Once`/env mutation needed). Every in-process test binary that builds a mock template thus
  runs its subprocesses over pipes.

### 4. `tests/binding_version_mismatch.rs`

- When spawning `argtuner` (line ~56), add `.env(argtuner_common::FORCE_PIPES_ENV, "1")` so its
  objective uses pipes for the `emit_binding_version` subprocess.

### 5. Mock bins — remove the timer

- Delete the `// Keep the PTY slave open…` comment + `argtuner_talkback::hold_stdout_open();`
  from each of the 5 `crates/mock-bin/src/bin/emit_*.rs`.

### 6. `bindings/rust/src/lib.rs`

- Remove `hold_stdout_open()` and `PTY_DRAIN_HOLD_MS` (unused after step 5).

## Notes

- No `std::env::set_var`, no `Once`, no process-environment mutation — the AtomicBool hook is
  UB-free and scoped to test processes.
- Mock runs no longer exercise the literal PTY transport (system under test is the parser /
  tuner logic, per user decision). Production keeps the PTY.
