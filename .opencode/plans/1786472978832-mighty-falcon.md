# Plan: README worked example of extracting a payload from a stdout feed

## Goal

Add a compact worked example to the README protocol section showing how a
`::ARGTUNER::` payload is pulled out of a noisy, ANSI-colored stdout feed
(ANSI-strip → prefix scan → JSON message), and assert it end-to-end with the
real parser so the docs can't drift from behavior.

Scope kept deliberately lean (per user): **only** the extraction + parsed JSON
message. No flattened field map, no scoring pipeline.

Context already in place: `argtuner_common::TalkbackMessage`, the schema echo +
`readme_echoes_current_schema` test, and the `line-ending` dev-dependency for
CRLF-safe comparison.

## Changes

### 1. `README.md` — worked example after the existing "For example:" block (~line 160)

```markdown
Extracting a payload from a stdout feed:
- Tap the protocol by scanning each stdout line for the literal `::ARGTUNER::`
  prefix: strip ANSI escape codes, find the first occurrence of the prefix, and
  JSON-parse everything after it. Lines without the prefix are ignored.
- Take this feed (`\x1b[` sequences are ANSI color codes):

<!-- protocol.example.feed -->
```text
Epoch 1/10: train loss 0.5234, val loss 0.6102
\x1b[36m::ARGTUNER::\x1b[0m{"type":"event","name":"model.epoch_end","fields":{"metric":"0.6102","epoch":"1"}}
```

- The second line, ANSI-stripped, is the prefix followed by one JSON message:

<!-- protocol.example.parsed -->
```json
{"type":"event","name":"model.epoch_end","fields":{"metric":"0.6102","epoch":"1"}}
```

- `tests/protocol_schema.rs` runs the real parser on this exact feed and
  asserts it produces exactly that message.
```

- `<!-- protocol.example.feed -->` / `<!-- protocol.example.parsed -->` are the
  machine markers the test scans for (same pattern as the schema echo).
- `\x1b` is shown as literal ASCII text so it renders readably; the test
  converts it to the real ESC byte before parsing.

### 2. `tests/protocol_schema.rs` — generalize extraction + new test

- Refactor `extract_readme_schema` into a generic
  `fn extract_fenced_block(readme: &str, marker: &str, fence_lang: &str) -> Option<String>`
  (same body, parameterized marker + fence language; keeps the
  `line_ending::LineEnding::normalize` handling). `extract_readme_schema` becomes
  a thin wrapper: `extract_fenced_block(readme, "<!-- protocol.schema.json -->", "json")`.
- Add test `readme_example_extracts_payload`:
  1. Extract the feed via `extract_fenced_block(readme, "<!-- protocol.example.feed -->", "text")`
     and `.replace("\\x1b", "\u{1b}")` so the ANSI codes are real ESC bytes.
  2. Extract the expected message via
     `extract_fenced_block(readme, "<!-- protocol.example.parsed -->", "json")`
     and deserialize it as `argtuner_common::TalkbackMessage`.
  3. Run the real parser: `argtuner::command::subprocess::parse_prefix_lines(&feed, "::ARGTUNER::")`.
  4. Assert exactly one line carries a payload, and it equals
     `ParsedItem::Event { name, fields }` derived from the expected message
     (`ParsedItem` derives `PartialEq`).
