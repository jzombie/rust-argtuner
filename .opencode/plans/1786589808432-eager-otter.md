# Port the window-view bridge into term-wm's `impl_view_component!`

## Goal

Arg t's Watch TUI currently reimplements a forwarding macro (`impl_view_window!` in
`src/cli/tui/mod.rs`) because term-wm's `impl_view_component!` can't express two
things its `&mut self` view form needs:

1. **Delegated `desired_height`** — its `height = <expr>` arm is a *constant*:
   `self`/`_width` inside the generated `desired_height` are macro-hygienic and
   unresolvable from a call-site argument (verified: `E0424 expected value,
   found module self`, `E0425 _width not found … due to macro hygiene`).
2. **Selection/hitbox forwarding** — the `&mut self` form drops the `&self`-queried
   `hitbox_id` / `selection_status` / `selection_text`, which the runner's copy
   pipeline reads off the focused window root.

**Fix:** port the bridge INTO term-wm by adding a third form to
`impl_view_component!` that takes the window's child field name and delegates the
`&self`-queryable metadata (height, hitbox, selection) to `self.<child>`. Then
argtuner deletes its local macro and uses the official one.

No new deps: argtuner patches term-wm to the local checkout
(`.cargo/config.toml`), so the macro update is picked up immediately.

## Design — new `impl_view_component!($ty, child: $child)` form

Semantics: an `&mut self` view that injects a single stateful child field
(`view! { <…>{ &mut self.$child }</…> }`). The macro body owns the `self`
identifier, so `self.$child` is hygiene-safe (field names are not hygienic); the
child name comes from the call site.

**Expansion — fully `$crate`-qualified UFCS, self-contained (no `Component`
trait import required at the consumer).** Paths mirror the existing arms exactly:
`Component`/`SelectionStatus` under `$crate::components::`, `Rect`,
`HitboxRegistry`/`HitboxId` under `$crate::hitbox_registry::`, `Event` under
`$crate::events::`, `ComponentContext` under `$crate::component_context::`,
`EventResult`/`TermWmAction` under `$crate::actions::`, `WindowKey` under
`$crate::window::`, backend `term_wm_render::RenderBackend`.

```rust
impl $crate::components::Component<$crate::actions::TermWmAction> for $ty {
    fn render(
        &mut self,
        backend: &mut dyn term_wm_render::RenderBackend,
        area: $crate::Rect,
        ctx: &$crate::component_context::ComponentContext,
        registry: &mut $crate::hitbox_registry::HitboxRegistry,
    ) {
        let mut view = self.view();
        $crate::components::Component::render(&mut view, backend, area, ctx, registry);
    }
    fn handle_events(
        &mut self,
        event: &$crate::events::Event,
        ctx: &$crate::component_context::ComponentContext,
    ) -> $crate::actions::EventResult<$crate::actions::TermWmAction> {
        let mut view = self.view();
        $crate::components::Component::handle_events(&mut view, event, ctx)
    }
    fn update(
        &mut self,
        action: $crate::actions::TermWmAction,
        ctx: &$crate::component_context::ComponentContext,
        actions: &mut ::std::collections::VecDeque<(
            $crate::window::WindowKey,
            $crate::actions::TermWmAction,
        )>,
    ) {
        let mut view = self.view();
        $crate::components::Component::update(&mut view, action, ctx, actions);
    }
    fn destroy(&mut self) {
        let mut view = self.view();
        $crate::components::Component::destroy(&mut view);
    }
    fn desired_height(&self, width: u16) -> u16 {
        $crate::components::Component::desired_height(&self.$child, width)
    }
    fn hitbox_id(&self) -> Option<$crate::hitbox_registry::HitboxId> {
        $crate::components::Component::hitbox_id(&self.$child)
    }
    fn clear_selection(&mut self) {
        $crate::components::Component::clear_selection(&mut self.$child);
    }
    fn selection_status(&self) -> $crate::components::SelectionStatus {
        $crate::components::Component::selection_status(&self.$child)
    }
    fn selection_text(&self) -> Option<String> {
        $crate::components::Component::selection_text(&self.$child)
    }
    fn take_pending_title(&mut self) -> Option<String> {
        let mut view = self.view();
        $crate::components::Component::take_pending_title(&mut view)
    }
    fn take_alternate_screen_transition(&mut self) -> Option<bool> {
        let mut view = self.view();
        $crate::components::Component::take_alternate_screen_transition(&mut view)
    }
    fn take_teardown_parts(
        &mut self,
    ) -> Option<(
        Box<dyn ::std::any::Any + Send + Sync>,
        ::std::thread::JoinHandle<()>,
    )> {
        let mut view = self.view();
        $crate::components::Component::take_teardown_parts(&mut view)
    }
    fn set_selection_enabled(&mut self, enabled: bool) {
        $crate::components::Component::set_selection_enabled(&mut self.$child, enabled);
    }
    fn paste(&mut self, text: &str) -> bool {
        $crate::components::Component::paste(&mut self.$child, text)
    }
}
```

Notes:
- `self.view()` temporaries are bound to `let mut view` before each UFCS call
  (no `E0599` trait-in-scope requirement; no double-borrow).
- `desired_height` reports the **child's** height, not the composed tree's chrome
  (document this; correct for full-window roots).
- Msg is inferred from the receiver (`&mut view` / `&self.$child` implement
  `Component<TermWmAction>`).
- Existing arms `($ty)` and `($ty, height = <expr>)` are **untouched** (their
  method-call style already requires `Component` in scope — existing behavior;
  the new arm is self-contained).

   `($ty:ty, child: $child:ident)` matcher arm (sketch above), and update the
   macro's doc comment (currently lines 254–267) to document all three forms and
   the hygiene rationale for why delegation is expressed as a field name.
2. `tests/view_consumer.rs` — switch `ChartsWindow` from
   `impl_view_component!(ChartsWindow, height = 2 + 2 + 3)` to
   `impl_view_component!(ChartsWindow, child: pane)`; update the
   `desired_height(30)` assertion from `7` to `3` (`pane.rows`, now delegated),
   and add a passthrough assertion (e.g. `selection_status()` /
   `selection_text()` equal to `pane`'s). This keeps the integration test
   exercising the new form against an argtuner-mirroring consumer.

   `[0.9.25-alpha]` section describing the `child:` delegation form.
