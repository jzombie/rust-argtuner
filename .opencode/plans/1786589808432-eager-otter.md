# Adopt the `view!` macro in the Watch TUI

## Goal

Adapt the argtuner Watch TUI (`src/cli/tui/mod.rs`, the only TUI file) to compose
its window components via the new `view!` macro, following the pattern term-wm
validated in `tests/view_consumer.rs`. **All 7 windows** become window structs
with `view(&mut self)` methods whose trees use **real structural `view!` nodes**
(a `<Box padding=1>` card wrapping the injected stateful child), not bare
escape-hatch roots.

No new dependencies: `term_wm::view` is re-exported by the patched umbrella
(term-wm 0.9.25-alpha, already a dep) and `term_wm_core::impl_view_component`
comes from the existing `term-wm-core` dep.

## Review dispositions (verified against term-wm source)

1. **Fake dogfooding (escape-hatch-only roots) — ADOPTED.** Every window tree
   now uses a structural tag: `<Box padding=1>{ &mut self.x }</Box>` (container +
   attribute + escape hatch), exercising the macro's composition/layout
   generation rather than a pure passthrough.
2. **`height = 0` erases dynamic child height — ADOPTED (defensively).** Use
   `height = term_wm::Component::desired_height(&self.x, _width)` so the window
   root delegates the child's dynamic height instead of hardcoding 0. Note:
   `desired_height` is never consulted by the tiling layout engine
   (`window_manager/layout.rs` and `term-wm-layout-engine` have no reader), and
   `BoxComponent::desired_height` returns 0 (stretch) when its child stretches,
   so behavior is unchanged today — this is contract-correctness/future-proofing.
3. **`&mut` form drops selection/hitbox at the window root — ADOPTED.** The
   runner's copy pipeline (`update_selection_snapshot`, runner.rs:883) queries
   the **focused window root**, and `ScrollViewComponent`/`TextRendererComponent`
   override `selection_status`/`selection_text` — so the 3 selection-enabled
   windows (Details/ProjectInfo/Frontier) would lose drag-select-copy. Fix: those
   three share one `TextWindow` type with a **hand-written `Component` impl** that
   forwards selection/hitbox/height to the child. (Hitbox: all children return
   `None` today, so no change there, but forwarding is future-proof.)
   `with_screen_area` clones the context and preserves `scroll_handle`, so
   Box-wrapping doesn't break charts/scroll viewports.

## Design

### Four window types for seven windows

| Windows | Struct | Tree |
|---|---|---|
| Trials | `TrialsWindow { sv: ScrollViewComponent<ListComponent> }` | `<Box padding=1>{ &mut self.sv }</Box>` |
| Charts | `ChartsWindow { sv: ScrollViewComponent<ChartsView> }` | `<Box padding=1>{ &mut self.sv }</Box>` |
| Details, ProjectInfo, Frontier | `TextWindow { sv: ScrollViewComponent<TextRendererComponent> }` | `<Box padding=1>{ &mut self.sv }</Box>` |
| Params, Metrics | `ToggleWindow { list: ToggleListComponent }` | `<Box padding=1>{ &mut self.list }</Box>` |

```rust
impl TrialsWindow {
    fn view(&mut self) -> impl Component<TermWmAction> + '_ {
        view! { <Box padding=1>{ &mut self.sv }</Box> }
    }
}
impl_view_component!(TrialsWindow, height = term_wm::Component::desired_height(&self.sv, _width));
```

- **ChartsWindow / ToggleWindow**: same `impl_view_component!(.., height =
  term_wm::Component::desired_height(&self.<sv|list>, _width))`.
- **TextWindow**: hand-written `impl Component<TermWmAction>` (see §"Hand-written
  TextWindow impl") because selection must be forwarded.

Verified: `view!` accepts a single escape-hatch root inside a container
(`Node::Block`, term-wm-view/src/lib.rs:241-260); the `&mut self` macro form
splices `height = $expr` into `fn desired_height(&self, _width: u16)` so `self`
and `_width` are in scope.

### Hand-written `TextWindow` impl

Mirrors the macro's `&mut self` forwarding but also forwards the `&self`-querying
metadata to the child (which is what `impl_view_component!`'s `&mut` form drops):

- `render` / `handle_events` / `update` / `destroy` / `take_pending_title` /
  `take_alternate_screen_transition` / `take_teardown_parts` → `self.view()`
- `desired_height(width)` → `term_wm::Component::desired_height(&self.sv, width)`
- `hitbox_id()` → `self.sv.hitbox_id()`
- `clear_selection()` / `set_selection_enabled(b)` / `paste(t)` →
  `self.sv.*`
- `selection_status()` → `self.sv.selection_status()`
- `selection_text()` → `self.sv.selection_text()`

## Changes to `src/cli/tui/mod.rs`

1. **Imports** — add `use term_wm::view;` (into the `term_wm::{…}` block) and
   `use term_wm_core::impl_view_component;` (beside
   `impl_component_delegate`). Use full paths (`term_wm::hitbox_registry::HitboxId`,
   `term_wm::components::SelectionStatus`) inside the hand-written impl to avoid
   extra imports.

2. **Add the 4 window structs** (+ `view()` methods + Component impls) near the
   `AppComponent` enum / `mk_*` factories.

3. **`AppComponent` enum**:
   ```rust
   enum AppComponent {
       Trials(TrialsWindow), Charts(ChartsWindow), Details(TextWindow),
       Params(ToggleWindow), Metrics(ToggleWindow),
       ProjectInfo(TextWindow), Frontier(TextWindow),
   }
   ```
   `impl_component_delegate!(AppComponent { … })` unchanged.

4. **`run()` window setup** — convert `mk_*` factories: `mk_trials_window`,
   `mk_charts_window`, `mk_text_window` (Details, ProjectInfo, Frontier),
   `mk_toggle_window("Hyperparameters" | "Metrics")`. `open_window(...)` calls
   unchanged in shape.

5. **Accessors** (`AppState::trials_sv`, `charts_sv`, `details_sv`, `params_list`,
   `metrics_list`, `project_info_sv`, `frontier_sv`) — match arms become
   `AppComponent::Trials(win) => Some(&mut win.sv)` (and `win.list` for the two
   toggle lists). Everything using them (`apply_chart_mode`,
   `push_data_to_components`, `refresh_trials`, `sync_param_toggles`,
   `selected_trial_idx`, `enabled_axes`) is otherwise untouched.

6. **New unit test** `mod view_tests` — mirror `term-wm/tests/view_consumer.rs`:
   - `window_roots_stretch`: `desired_height(30) == 0` for all 7 windows (via
     delegation; children still stretch).
   - `view_windows_render_injected_children`: build a `TrialsWindow`, set list
     items via `update_items`, render through `RatatuiBackend`/`Buffer` with a
     `ComponentContext` and assert the item text appears; render a `ChartsWindow`
     (empty trials → "No trials loaded.") and a `ToggleWindow` (toggle item
     renders) — verifies the `<Box>` tree + injection render without panic.
   - `text_window_forwards_selection`: `TextWindow::set_selection_enabled(true)`
     and assert `selection_status()`/`selection_text()` delegate to `self.sv`
     (passthrough wiring compiles and routes to the scroll view).

### Unchanged
- WM-level behavior: window titles, `set_closable(k, false)`, `transition_window`
  (chart-mode mapping), `mark_layout_dirty`, keybindings, `handle_app_event`,
  the scheduler/render host, `ChartsView` itself, SQL layer, pure logic fns.
- `key_tests` / `frontier_tests` (pure logic) — unaffected.
- No `Cargo.toml` / feature changes.
