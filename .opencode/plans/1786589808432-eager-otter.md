# Re-extract the SDK into a lightweight `argtuner-sdk` crate

## Goal

Extract the SDK (currently `argtuner::sdk`, un-gated by the `cli` feature in the
main crate) into a new, self-contained workspace crate **`argtuner-sdk`** so ML
training workloads link only the SDK — not the CLI/TUI (ratatui, crossterm,
term-wm\*, rusqlite, argmin, portable-pty, …).

Decisions confirmed with the user:
1. **Clean break**: `argtuner` no longer re-exports the SDK. `argtuner` = the
   CLI/tuner only; `argtuner-sdk` = the Rust binding for your training app.
   Existing `argtuner::init` / `argtuner::emit_*` / `argtuner::Params` users
   migrate to `argtuner_sdk`.
2. **Derive emits `::argtuner_sdk::` paths** (mandatory): `#[talkback_args]`
   expansion must resolve `Params`/`ParamHint`/`ParamKind`/`clap` in the
   lightweight SDK crate so SDK-only consumers compile without the CLI crate.

## Current coupling points (verified)

- `src/sdk.rs` (632 lines) is the entire SDK. Its only dependency into the main
  crate is `crate::constants::{PLACEHOLDER_TRIAL_DIR, PLACEHOLDER_TRIAL_ID}`
  (`is_reserved()`). Everything else uses `argtuner-common`, `argtuner-derive`,
  `clap`, `serde`, `serde_json`, `toml_edit`.
- `crates/argtuner-derive/src/lib.rs` generates hardcoded `::argtuner::` paths.
- `crates/deprecated/argtuner-talkback` depends on `argtuner` (full CLI crate);
  `argtuner-talkback-derive` depends on `argtuner-derive`.
- `crates/mock-bin` uses `argtuner::emit_event` (test-only subprocesses).
- `examples/*` (`linear_regression`, `interactive_probe`,
  `loss_pattern_generator`, `pareto_demo`) use `argtuner_derive::talkback_args`
  + `argtuner::init`/`emit_*`.
- `tests/talkback_template.rs` uses `argtuner::{Params, render_template_*}`.
- Root `README.md` (included as `argtuner`'s crate docs; `rust,no_run` blocks
  are doctests) shows `argtuner::{init, emit_metrics, is_tuning_active}` +
  `argtuner_derive::talkback_args`.
- `rust-tests.yml` has an "SDK-only build" step checking
  `cargo check -p argtuner --no-default-features`.

## Design

### 1. New crate: `crates/argtuner-sdk/`

- **`Cargo.toml`**: `name = "argtuner-sdk"`, `version.workspace = true`,
  `edition.workspace = true`, `repository/license/keywords/categories` from
  workspace. Dependencies (all workspace):
  - `argtuner-common` (protocol types/constants)
  - `argtuner-derive` (the `#[talkback_args]` macro)
  - `clap` (re-exported for derive-generated code; no extra features)
  - `serde` (features `["derive"]`; re-exported for consumers)
  - `serde_json`
  - `toml_edit` (features `["serde"]`)
  - No dev-deps.
- **`src/lib.rs`**: move `src/sdk.rs` body verbatim, then:
  - `use argtuner_common::TalkbackMessage;` → add
    `argtuner_common::{PLACEHOLDER_TRIAL_DIR, PLACEHOLDER_TRIAL_ID}` (new
    constants, see §3) and use them in `ParamHint::is_reserved()`.
  - Update doc comments referencing `argtuner::` → `argtuner_sdk::`.
  - `#[macro_export] macro_rules! emit_metrics` stays; `$crate::emit_epoch_end`
    resolves to `argtuner_sdk::emit_epoch_end`.
- **`README.md`** (crate docs via `#![doc = include_str!("../README.md")]`):
  describe the SDK, the stdio protocol, the `ARGTUNER_TUNING` marker
  (no-op when unset), and add the required documentation:
  > The per-project overhead of depending on `argtuner-sdk` is extremely low —
  > it pulls in only a handful of small crates (clap, serde, serde_json,
  > toml_edit, argtuner-common, argtuner-derive) and does nothing at runtime
  > unless `ARGTUNER_TUNING` is set. If performance is paramount it can be
  > skipped entirely: emit the raw `::ARGTUNER::` JSON lines documented in the
  > protocol schema (see `argtuner-common` / the root README).
  Must pass `RUSTDOCFLAGS="-D warnings"` (no broken intra-doc links) since CI
  docs the whole workspace.

### 2. `crates/argtuner-derive`

- Replace every `::argtuner::` in generated code with `::argtuner_sdk::`
  (ParamKind, ParamHint, Params, clap paths). Update the module doc comment.
- Doctest: `<ModelParams as argtuner::Params>` → `<ModelParams as argtuner_sdk::Params>`.
- `Cargo.toml` dev-dependency: `argtuner = { path = "../.." }` →
  `argtuner-sdk = { path = "../argtuner-sdk" }` (path-only, no version — keeps
  the existing publish-stripping trick). Update README if it names `argtuner`.
- (Dev-dep cycle `argtuner-sdk` ↔ `argtuner-derive` is allowed in-workspace,
  same as the existing `argtuner-derive` dev-dep on the root package.)

### 3. `crates/common` (`argtuner-common`)

- Move `PLACEHOLDER_TRIAL_ID` / `PLACEHOLDER_TRIAL_DIR` here (they are
  protocol-reserved placeholder tokens shared by SDK template generation and
  the CLI renderer/inspector). Add to `crates/common/src/lib.rs` root with
  doc comments.

### 4. Main `argtuner` crate — clean break

- `src/lib.rs`: delete `mod sdk; pub use sdk::*;` and its doc comment. Keep
  `pub mod constants; pub use constants::*;` and all `#[cfg(feature = "cli")]`
  modules. Delete `src/sdk.rs`.
- `src/constants.rs`: replace the two `pub const PLACEHOLDER_*` with
  `pub use argtuner_common::{PLACEHOLDER_TRIAL_DIR, PLACEHOLDER_TRIAL_ID};`
  (CLI call sites `inspect.rs`, `validate.rs`, `trial/mod.rs` unchanged).
- Root `Cargo.toml`:
  - Add `crates/argtuner-sdk` to `[workspace] members`.
  - Add `argtuner-sdk = { path = "crates/argtuner-sdk", version = "0.1.2-alpha" }`
    to `[workspace.dependencies]`.
  - `[dependencies]`: remove `argtuner-derive` (now only reachable via the SDK).
    Keep everything else (`argtuner-common`, `clap`, `serde`, `serde_json`,
    `toml_edit`, and all `cli`-feature deps).
  - `[dev-dependencies]`: add `argtuner-sdk.workspace = true` (needed by
    examples, `tests/*`, and README doctests; dev-deps are available to all of
    those and keep the CLI's runtime deps clean). **Note (verified):** no CLI
    runtime code (lib or bins) references any SDK item — `render_template_*`,
    `Params`, `ParamHint`, `ParamKind`, `is_tuning_active`, `parse_args`,
    `print_protocol_schema` appear only inside `src/sdk.rs` itself, and
    `SearchSpace`/`ParamSpec` are defined in `src/search_space/mod.rs` (which
    stays). So `argtuner-sdk` belongs in dev-dependencies only.

### 5. Deprecated shims → point at the SDK

- `crates/deprecated/argtuner-talkback`: dep `argtuner.workspace = true` →
  `argtuner-sdk.workspace = true`; lib.rs re-exports `pub use argtuner_sdk::*;`
  with an updated deprecation note ("use `argtuner-sdk` directly, e.g.
  `use argtuner_sdk::{init, emit_metrics, talkback_args}`"). README updated.
- `crates/deprecated/argtuner-talkback-derive`: dep `argtuner-derive.workspace =
  true` → `argtuner-sdk.workspace = true`. Keep the existing **`pub use`
  re-export**, just retarget it: `pub use argtuner_sdk::talkback_args;`
  (deprecation note updated). Re-exporting proc macros via `pub use` is stable
  since Rust 1.57, and this exact pattern already compiles in this crate today
  (`pub use argtuner_derive::talkback_args;`) — proven by the green workspace
  build. Do NOT call the proc macro as a function (illegal), and do NOT need a
  helper-fn refactor; `argtuner_sdk::talkback_args` is a public proc-macro item
  reachable through the same path machinery. README updated.

### 6. In-workspace consumers

- `crates/mock-bin`: dep `argtuner.workspace = true` →
  `argtuner-sdk.workspace = true`; update `src/bin/*.rs` `argtuner::emit_event`
  → `argtuner_sdk::emit_event`. Proves the SDK alone is sufficient for protocol
  emission.
- `examples/*/main.rs` (`linear_regression`, `interactive_probe`,
  `loss_pattern_generator`, `pareto_demo`): use
  `argtuner_sdk::{init, emit_metrics, emit_epoch_end, talkback_args}`.
- `tests/talkback_template.rs`: `argtuner::{Params, render_template_toml,
  render_template_command}` → `argtuner_sdk::…`; `argtuner_derive::talkback_args`
  → `argtuner_sdk::talkback_args`. Keep `argtuner::{UnifiedConfig, ParamSpec}`
  (CLI types). Other tests (`dry_run`, `trial_flow`, …) use CLI types only and
  are unchanged.

### 7. Docs (`README.md`)

- Quickstart / SDK section / TUI-framework snippets: switch to
  `argtuner_sdk::{init, emit_metrics, is_tuning_active, talkback_args}`; clarify
  `argtuner` = the tuner CLI, `argtuner-sdk` = the Rust binding for your app.
- Add the low-overhead / skippable SDK documentation (§1 text) in the SDK
  section.
- Do NOT touch the marker-annotated blocks (`protocol.schema.json`,
  `config.example`, `config.inspect.output`, `protocol.example.*`) —
  `tests/readme_assertions.rs` asserts them byte-identical.

### 8. CI (`rust-tests.yml`)

- Replace the "SDK-only build" step with:
  `cargo check -p argtuner-sdk --lib` (the new lightweight SDK build) plus the
  existing `cargo check -p argtuner --no-default-features --lib`.
  Optionally assert `cargo tree -p argtuner-sdk` contains no heavy crates
  (ratatui/crossterm/rusqlite/term-wm/argmin).

## Verification

1. `cargo build --workspace` (includes both deprecated shims, verifying the
   delegating wrapper in `argtuner-talkback-derive` compiles)
2. `cargo check -p argtuner-sdk` — compiles alone, no heavy deps.
3. `cargo tree -p argtuner-sdk` — confirm no ratatui/crossterm/rusqlite/
   term-wm/argmin in the tree.
4. `cargo check -p argtuner --no-default-features --lib`
5. `cargo test --workspace --all-features --lib --bins --tests --examples -- --include-ignored`
   (includes README doctests, `talkback_template`, end-to-end trial tests via
   mock-bin — proving the SDK-only mock subprocesses speak the protocol).
6. `cargo fmt --all -- --check` and `cargo clippy --workspace --all-targets
   --all-features -- -D warnings`
7. `RUSTDOCFLAGS="-D warnings" cargo doc --workspace --no-deps
   --document-private-items`
8. If tools installed: `cargo sort --workspace --check` (run `cargo sort` to
   fix ordering of the new `argtuner-sdk` entries) and
   `cargo udeps --workspace --all-targets --all-features` (verifies the dropped
   `argtuner-derive` dep and new dev-dep are clean).
9. Smoke-test a standalone SDK consumer (temp crate in
   `/var/folders/.../T/opencode` depending only on `argtuner-sdk`): run with
   `#[talkback_args]` + `init` + `emit_metrics!`; assert plain runs print no
   `::ARGTUNER::` lines and `ARGTUNER_TUNING=1` runs do.
