# Feature plan: `[[skip]]` — exclude parameter configurations from tuning runs

**Semantics (agreed):** skipped configs are (a) never evaluated — no subprocess, no trial
row, no budget burned — and (b) reflected in `argtuner plan` output. Rules are partial HP
assignments in `argtuner.toml`; one shared `SkipList` type is the single matcher used by
every consumer (eval choke point, discrete pool, plan, validation).

**Decisions made with user:**
- PSO: a skipped sample returns penalty cost `f64::INFINITY` (scores are normalized
  lower-is-better; `Goal::Max` already negates at `src/command/objective.rs:686`).
- Enforcement prefix: new `invalid_config: skipped_config` constant so the existing
  invalid-config machinery (refund + resample in `run_scheduled`) is reused.
- Guard/promotion policy: see **Open questions** at the end (user requested these be
  recorded as questions in this plan). The body below recommends: guard exemption
  (semantic compare modulo `skip`) + skip rules gate **fresh rung-0 configs only**.

## 1. Data model & parsing

### TOML shape (root-level, top of `argtuner.toml`)

```toml
template = "python train.py --lr {lr} ..."

# Exclude configurations from tuning: a rule fires when EVERY key equals the
# config's corresponding hp.* field. Fewer keys = broader (partial) match.
[[skip]]
optimizer = "sgd"          # matches any config with hp.optimizer = "sgd"

[[skip]]
batch = 32
lr = 0.01                  # multi-key rule: both must match

[project]
metric_key = "metric"
...

[scheduler]
type = "successive_halving"
n_trials = 9
```

### Types — new file `src/skip.rs`

```rust
use std::collections::BTreeMap;
use serde::{Deserialize, Serialize};
use crate::constants::HP_PREFIX;
use crate::search_space::{ParamSpec, SearchSpace};

/// One scalar value in a skip rule (TOML scalar).
#[derive(Debug, Clone, Serialize, Deserialize, PartialEq)]
#[serde(untagged)]
pub enum SkipValue { Bool(bool), Int(i64), Float(f64), Str(String) }

/// `[[skip]]` — a partial assignment of search-space params.
/// All keys are parameter names; unknown names are rejected by `SkipList::resolve`
/// (checked against the space), not by serde.
#[derive(Debug, Clone, Serialize, Deserialize, PartialEq)]
pub struct SkipRule {
    #[serde(flatten)]
    pub assignments: BTreeMap<String, SkipValue>,
}

/// Resolved, canonical skip matcher — THE unified skip type.
#[derive(Debug, Clone, Default)]
pub struct SkipList {
    /// Each rule: keys canonicalized to `hp.<param>`, values canonicalized to the
    /// exact strings `ParamSpec::value_from_unit` renders.
    rules: Vec<BTreeMap<String, String>>,
}
```

## 2. The unified skip module (`src/skip.rs`)

```rust
impl SkipList {
    /// Validate + canonicalize raw rules against the search space.
    /// Errors (all surfaced through `validate_project_config`):
    ///   - "skip rule #N must set at least one parameter"     (empty rule matches everything)
    ///   - "skip rule references unknown parameter 'x'"
    ///   - "skip rule value 'v' is not a valid value for parameter 'x' (allowed: ...)"
    ///     — for discrete params: membership in `ParamSpec::discrete_values()`
    ///       (gives typo detection for Choice/Bool/stepped numerics);
    ///       for continuous params: `ParamSpec::validate()` (range/step check).
    pub fn resolve(rules: &[SkipRule], space: &SearchSpace) -> Result<Self, String>;

    /// THE predicate. `hp_fields` is the full rendered field map
    /// (from `SearchSpace::fields_from_unit` / `rendered.fields`); rule keys are
    /// hp.-prefixed, so non-hp keys are simply never looked up.
    /// Semantics: any(rule: every (k,v) present-and-equal in hp_fields).
    /// Empty SkipList → `false` (no special-casing needed at call sites).
    pub fn matches(&self, hp_fields: &BTreeMap<String, String>) -> bool;

    /// Like `matches`, but returns the first matching rule (for error/log text).
    pub fn find_match(&self, hp_fields: &BTreeMap<String,String>) -> Option<&BTreeMap<String,String>>;

    /// Match a discrete-pool assignment (`params` names + values, `""` = inactive
    /// sentinel): builds the hp map skipping empty values — identical to
    /// `DiscreteConfigPool::apply_to_overrides` (random.rs:98-108).
    pub fn matches_values(&self, params: &[String], values: &[String]) -> bool;

    /// (excluded, total) counts over the FULL discrete space, or None when the
    /// space is not enumerable within `MAX_RANDOM_EXHAUSTIVE_CONFIGS`.
    pub fn excluded_counts(&self, space: &SearchSpace) -> Option<(usize, usize)>;

    /// Human labels for plan: ["optimizer = sgd", "batch = 32, lr = 0.01"].
    pub fn labels(&self) -> Vec<String>;

    pub fn is_empty(&self) -> bool;
}
```

### Value canonicalization (must equal `value_from_unit` rendering)

`ParamSpec::value_from_unit` (src/search_space/mod.rs:530-574) renders:
- Float → `format_value(v, format)` (:690-705, default `format!("{value}")`,
  `{:.3}`/`{:.4}`/`{:.6}` special-cased) — **make `format_value` `pub(crate)`**.
- Int → `i64::to_string()`; Choice → declared string; Bool → `"true"`/`"false"`.

`resolve` canonicalizes each rule value through the *param's* rendering:

| spec \ value | Bool | Int | Float | Str |
|---|---|---|---|---|
| Float | error | `format_value(i as f64, fmt)` | `format_value(f, fmt)` | parse→f64→format, else error |
| Int | error | `i.to_string()` | `f.fract()==0 → (f as i64).to_string()`, else error | parse→i64→string, else error |
| Choice | error* | `i.to_string()` | `format!("{}",f)` | `s.clone()` |
| Bool | `b.to_string()` | error | error | must be `"true"`/`"false"` |

Then validate: `discrete_values()` present → require membership (error lists allowed
values, truncated after ~10); otherwise `spec.validate(&canonical)`.
\*a Bool literal for a Choice is rejected — users write `"true"` strings.

### Matching semantics — conditional/inactive params

`fields_from_unit` **omits** inactive conditional params (mod.rs:68-77; sentinel
handling documented in `collect_used_configs` random.rs:345-349). Therefore:
- Rule key on an inactive param → key absent from the config's map → **no match**.
  (A rule can never accidentally fire on a config where the param doesn't exist.)
- Multi-key rule where one key is inactive → no match (correct: config can't agree).
- `matches_values` mirrors the pool's `""` sentinel by skipping empty values.

### Float caveat (document in README)

Matching is exact canonical-string equality. On *continuous* floats the rendered
value (`format!("{min + (max-min)*c}")`) is effectively random, so a rule like
`lr = 0.01` will almost never fire. Skip rules should target discrete params
(Choice/Bool/Int/stepped Float/`format`-pinned Float). Validation cannot detect
this case (the value is in range); README documents it.

### 3a. Shared enumerator extraction (pool ↔ plan)

New method on `SearchSpace` (`src/search_space/mod.rs`) — the recursion currently at
`sampler/random.rs:362-396` plus the product-cap pre-check at :60-69, moved verbatim:

Notes: the current recursion only filters `used` at full depth (no branch pruning),
so filtering *after* enumeration is behavior-identical.

- `DiscreteConfigPool::new(space, store, skip: &SkipList)` (random.rs:57-87):
  ```rust

      else { return Ok(None) };
  let used = collect_used_configs(store, &params, &conditional)?;

      .filter(|cfg| !used.contains(cfg) && !skip.matches_values(&params, cfg))
  ```

  → **pre-exclusion point #1**.
- `SkipList::excluded_counts(space)` reuses it for plan/validation (no DB involved;
  counts are over the full space, independent of already-run trials).

### 3b. Eval-time choke point — covers ALL samplers

`src/command/objective.rs` — `CommandObjective` gains field `skip: SkipList`, builder
`.with_skip_list(SkipList)` (defaults to empty → zero behavior change for all existing
callers/tests), accessor `pub fn skip_list(&self) -> &SkipList`.

Insert the check inside `eval_with_overrides_internal`, in the existing
`if existing_fields.is_none()` block (:493), **before** the duplicate check (:494-503)
— skip is cheaper (map lookups) and semantically primary ("never evaluated"):

```rust
if existing_fields.is_none() {
    let rung: usize = effective_overrides.fields.get(FIELD_TRIAL_RUNG)
        .and_then(|v| v.parse().ok()).unwrap_or(0);   // absent (PSO) ⇒ 0
    if rung == 0 && let Some(rule) = self.skip.find_match(&rendered.fields) {
        return Err(format!("{SKIPPED_CONFIG_PREFIX} ({})", fmt_rule(rule)));
    }
    // …existing duplicate check unchanged…
}
```

- **Nothing persists**: this returns a plain `Err` *before* the `Running` append at
  :539-552 and outside the `EvalError::InvalidConfig` arm (:866-876), so no Error row,
  no artifact dir, no budget side effects — same as the duplicate path today.
- **`rung == 0` condition**: SHA `retry_trial` (:218-246) re-issues the *same
  config_id* with resampled coords, and promotion re-evals at rung>0 with a new
  trial_id but an existing rung-0 `Ok` row. Gating on fresh rung-0 evals means:
  - resume of an in-flight rung-0 trial (`existing_fields.is_some()`) → continues;
  - SHA promotion (rung>0) → continues (preserves parent-artifact lineage and budget
    accounting — see Open question #1);
  - PSO (no `trial.rung` field, `config_id` absent) → always checked;
  - Fixed (rung always 0) → always checked for new configs.
- **Ordering vs duplicate**: skip first, then `find_duplicate_config`
  (store.rs:427-458) — unchanged.

### 3d. Driver handling — `run_scheduled` (`src/sampler/random.rs:115-254`)

Used by `run_random` **and** `run_pareto`, so both are covered.

```rust

let is_skipped   = err.starts_with(SKIPPED_CONFIG_PREFIX);
if is_duplicate || is_skipped {
    // existing shared block (:179-228): build DiscreteConfigPool lazily —
    // now with the skip list — substitute a non-skipped, unused config via
    // pool.assign_values + apply_to_overrides, re-eval, on success record & continue.
    // counter: duplicate_retries (rename to `resample_retries`), still bounded by
    // MAX_DUPLICATE_RETRIES = 50, reset on any success.
}
if err.starts_with(INVALID_CONFIG_PREFIX) && scheduler.retry_trial(trial.token) {
    // refund + fresh sample. Message:
    eprintln!("trial skipped: {err}; resampling")   // when is_skipped
    eprintln!("trial invalid: {err}; retrying")      // otherwise (existing)
    …existing forget_config / completed.remove…
}
```

- **Discrete spaces**: first skip builds the pool (which already excludes skipped
  combos) → deterministic substitution; pool exhausted + everything skipped → the
  shared 50-retry bound fires. Update the bound error message at :223-227:
  `"unable to find a usable config after {MAX} retries; search space may be
  exhausted, too small for n_trials, or covered by [[skip]] rules"`.
- **Continuous spaces**: pool is `None` → falls straight to `retry_trial`
  (Fixed: refund + new `config_id`/coords, fixed.rs:126-131; SHA: refund + resample
  coords for same `config_id`, successive_halving.rs:218-246). The shared counter
  bounds a mostly-skipped space (50 *consecutive* skips abort with the message above).
- Skipped configs are never inserted into the `completed` map → on resume the token
  simply wasn't recorded and gets re-sampled (and re-skipped if it matches again).

### 3e. PSO — `ControllableObjective::eval` (`src/checkpoint.rs:66-101`)

After `let result = self.inner.eval(coords);`, before cache insert / duplicate recovery:

```rust
if let Err(err) = &result && err.starts_with(SKIPPED_CONFIG_PREFIX) {
    eprintln!("trial skipped: {err}; assigning worst cost");
    return Ok(f64::INFINITY);   // no row persisted, no command run, swarm steers away
}
```

- Not cached (rules may change between sessions; the predicate check is cheap).
- Never aborts the argmin executor (unlike propagating `argmin::core::Error::msg`).
- Cache-first ordering stays: a config scored *before* a rule was added still returns
  its real cached score (it was genuinely evaluated — fine).

## 5. Validation & config-guard integration

### `src/validate.rs` — new `validate_skip_rules`, called from `validate_project_config` (after `validate_objectives`, :25)

```rust
fn validate_skip_rules(config: &ProjectConfig, space: &SearchSpace) -> Result<(), String> {
    let skip = SkipList::resolve(&config.skip, space)?;
    if let Some((excluded, total)) = skip.excluded_counts(space)
        && total > 0 && excluded == total {
        return Err("skip rules exclude every configuration in the search space".into());
    }
    Ok(())
}
```

Checks: empty rule, unknown param, type/canonicalization errors, out-of-domain values
(strong: `discrete_values()` membership for discrete params), and whole-space coverage
when enumerable.

### `src/trial/store.rs` — guard exemption (`ensure_project_config`, :333-362)

Recommended policy (see Open question #2): skip-only edits pass the guard, and —
combined with the `rung == 0` gate — they can never kill an in-flight or promoted
config.

```rust
Some(existing) => {
    if existing == config_text { return Ok(()); }
    if allow_override { return self.db.save_project_config(config_text); }
    if !self.db.has_any_trials()? { return self.db.save_project_config(config_text); }
    // NEW: skip-rule edits (and comment/whitespace-only edits) don't change any
    // recorded trial — refresh stored text and resume.
    if configs_equivalent_modulo_skip(&existing, config_text) {
        return self.db.save_project_config(config_text);
    }
    …existing refusal + diff (:351-359)…
}
```

```rust
/// Semantic comparison: parse both texts to toml::Value, drop the top-level
/// "skip" key from both, compare Values. Both sides already had to parse as
/// valid TOML to reach this point; if either fails, return false (refuse).
fn configs_equivalent_modulo_skip(a: &str, b: &str) -> bool {
    let (Ok(mut l), Ok(mut r)) = (a.parse::<toml::Value>(), b.parse::<toml::Value>())
        else { return false; };
    for side in [&mut l, &mut r] {
        if let toml::Value::Table(t) = side { t.remove("skip"); }
    }
    l == r
}
```

- No new dependency (`toml` already used by `project/mod.rs`).
- Side effect (intended): comment/whitespace-only edits also become exempt — they
  cannot affect run behavior; stored text is refreshed so the refusal diff for any
  *later* real change compares against fresh text.
- `dry_run` never reaches the guard (temp store, tuner/mod.rs:63) — unchanged.

## 8. Risks / edge cases

- **Resume**: skip edits refresh stored text via the guard exemption; completed
  trials are untouched; `find_duplicate_config` still blocks re-running Ok configs.
  A config completed *before* a rule was added may still appear in `plan`-time
  history — new samples avoid it.
- **TUI (`watch`)**: read-only over trials — skipped configs produce no rows, so
  nothing renders differently. Out of scope; optionally showing the rule count in a
  header later.
- **Continuous spaces**: enumeration impossible → pool `None`, plan shows
  `n/a`; enforcement relies on eval-time check + bounded resample (50 consecutive
  skips abort with an explicit message). Exact-string float caveat documented.
- **Mid-promotion / mid-run rule edits**: gated by `rung == 0` — see Open questions
  #1/#2; budget and parent-artifact lineage never touched.
- **`plan --config-id`**: orthogonal; skip lines render before the config-path block.
- **PSO with INFINITY**: if *every* particle lands on skipped regions, `best_cost`
  may print `inf` (cosmetic; PSO-only-validate rejects non-Fixed schedulers, and
  whole-space exclusion is caught by validation when enumerable).
- **PSO trial cache**: may serve real scores for now-skipped configs — correct
  (they were evaluated); never *executes* a skipped config.
- **Serde flatten round-trip**: covered by an explicit `save_unified_config` →
  re-parse unit test (step 4).
- **SHA `retry_trial` keeps `config_id`**: a skipped rung-0 config that fails pool
  substitution is resampled under the same id; because a skip never persists a row,
  the next eval is still checked (no accidental exemption via stale Error rows —
  exemption keys off `rung`, not row history).
