# Purge `String::leak` from the derive's non-literal `default` handling

The only leak in the workspace is `crates/argtuner-derive/src/lib.rs:216`: for
`#[param(default = <const expr>)]` on numeric/bool fields (the const's value is unknowable
at macro-expansion time), the generated lazy fn does `format!("{}", expr).leak()` to mint a
`&'static str`. Fix by borrowing from a `static OnceLock<String>` instead — same lifetime
guarantee, zero leak. `TunerParam` stays `Copy` with all 14 fields; no API change.

## Change — `crates/argtuner-derive/src/lib.rs` (`lazy_default_fns`, ~:211-218)

```rust
// before
fn #f() -> &'static str {
    static VALUE: ::std::sync::OnceLock<&'static str> = ::std::sync::OnceLock::new();
    *VALUE.get_or_init(|| ::std::format!("{}", #expr).leak())
}

// after
fn #f() -> &'static str {
    static VALUE: ::std::sync::OnceLock<::std::string::String> = ::std::sync::OnceLock::new();
    VALUE.get_or_init(|| ::std::format!("{}", #expr)).as_str()
}
```

`OnceLock<String>` is a static, so `.get_or_init(...)` returns `&String` with a `'static`
lifetime and `.as_str()` yields `&'static str` — LSan/Valgrind see a static root, not a
leak. `TunerParam.default: Option<&'static str>` and the already-present
`OnceLock<Vec<TunerParam>>` return are unchanged.
