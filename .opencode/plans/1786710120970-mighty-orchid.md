# Enforce enum-identifier `role` (drop string literals)

Follow-up to the `role` redesign: `#[param(role = ...)]` must take an enum-style
identifier/path (`role = tune`, `role = ParamRole::Tune`,
`role = argtuner_sdk::ParamRole::Tune`) and reject string literals. This is a
small, single-file core change plus a mechanical migration of every in-repo
usage. No `ParamRole` import is required by callers: the derive matches the
attribute tokens textually and strips `#[param]` before re-emitting the struct,
so the compiler never resolves the path.

## Core change — `crates/argtuner-derive/src/lib.rs`

### 1. New role parser (replaces `out.role = expr_string(value)` at ~line 423)

In `parse_param_attrs`, the `"role"` arm parses `&syn::Expr` directly and stores
the canonical lowercase variant string in `out.role: Option<String>` — all
downstream logic (matrix check at ~479, injected whitelist at ~501, main-loop
role emission) is unchanged.

**Every `syn::Error` is spanned on `expr` (the value token), not the whole
field**, so diagnostics/IDE markers underline exactly the invalid `role = ...`
argument. `parse_role` takes only `expr` (no `field`).

- Accept `syn::Expr::Path` only. Extract the **terminal path segment** ident
  (works for `tune`, `ParamRole::Tune`, `argtuner_sdk::ParamRole::Tune`).
- Map via `eq_ignore_ascii_case`: `fixed`/`Fixed` → `"fixed"`,
  `tune`/`Tune` → `"tune"`, `injected`/`Injected` → `"injected"`,
  `cli`/`Cli` → `"cli"`.
- **Distinct error branches, each spanned on `expr`:**
  - `syn::Expr::Lit { lit: Lit::Str(_) }` → "string literals are no longer
    accepted for `role`; use `role = tune` or
    `role = argtuner_sdk::ParamRole::Tune`"
  - any other non-path expression (`role = 42`, tuples, …) → "`role` must be
    an enum identifier or path (e.g. `role = tune` or
    `role = argtuner_sdk::ParamRole::Tune`)"
  - unknown terminal ident → "unknown `role` `{terminal}`; expected `fixed`,
    `tune`, `injected`, or `cli`"

Implementation sketch:

```rust
fn parse_role(expr: &syn::Expr) -> Result<Option<String>, syn::Error> {
    let terminal = match expr {
        syn::Expr::Path(p) => p
            .path
            .segments
            .last()
            .map(|s| s.ident.to_string())
            .ok_or_else(|| syn::Error::new_spanned(expr, "empty path provided for `role`"))?,
        syn::Expr::Lit(syn::ExprLit { lit: syn::Lit::Str(_), .. }) => {
            return Err(syn::Error::new_spanned(
                expr,
                "string literals are no longer accepted for `role`; use `role = tune` \
                 or `role = argtuner_sdk::ParamRole::Tune`",
            ));
        }
        _ => {
            return Err(syn::Error::new_spanned(
                expr,
                "`role` must be an enum identifier or path (e.g. `role = tune` or \
                 `role = argtuner_sdk::ParamRole::Tune`)",
            ));
        }
    };

    let canonical = match terminal.as_str() {
        s if s.eq_ignore_ascii_case("fixed") => "fixed",
        s if s.eq_ignore_ascii_case("tune") => "tune",
        s if s.eq_ignore_ascii_case("injected") => "injected",
        s if s.eq_ignore_ascii_case("cli") => "cli",
        _ => {
            return Err(syn::Error::new_spanned(
                expr,
                format!(
                    "unknown `role` `{terminal}`; expected `fixed`, `tune`, `injected`, or `cli`"
                ),
            ));
        }
    };

    Ok(Some(canonical.to_string()))
}
```

### 2. Update error strings

- The "unknown role" fallback at ~480 becomes an unreachable safety net (kept);
  its message mentions identifier forms.
- Keep `skip`-removal and injected-whitelist messages as-is (they're correct;
  they stay spanned on the field, since they describe whole-attribute problems).

## Migration (mechanical: `role = "x"` → `role = x`)

Use bare snake_case identifiers in all examples/docs (consistent with the other
snake_case hint keys); the qualified forms remain supported.

- `crates/argtuner-derive/src/lib.rs` — doc-comment example (~13-28)
- `examples/linear_regression/main.rs`, `examples/loss_pattern_generator/main.rs`,
  `examples/pareto_demo/main.rs`, `examples/interactive_probe/main.rs`
- `tests/talkback_template.rs`
- `README.md` — quickstart struct, "Declaring parameters" table/example
- `crates/argtuner-sdk/README.md` — usage example
- `CHANGELOG.md` — Unreleased entry: update the `role = ...` examples to
  identifier form and note that string literals are rejected

## Out of scope
- No runtime changes: `ParamRole` enum, `ParamHint`, renderers, `is_tunable()`
  all stay as-is.
- No change to how `parent`/`parent_values`/`long`/etc. are parsed.
