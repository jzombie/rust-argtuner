# SDK: explicit `role` for every parameter (breaking redesign)

Replace the implicit, type-dependent tunability rules with one explicit orthogonal axis: **who supplies the value**. `min`/`max`/`choices`/`step`/`log`/`parent*` become plain constraint data that is only valid on `role = "tune"`. Default role is `fixed` for **all** types (kills the "bare bool is tunable" surprise). Old hints are removed entirely (breaking) with helpful compile errors.

## New `role` model

**`default` is optional for every role.** It only changes `fixed` rendering and clap requiredness — it is never a mandatory attribute (so unannotated fields default to `fixed` cleanly).

| `#[param(role = ...)]` | Meaning | Required | Template / `[space]` |
|---|---|---|---|
| `fixed` (**default**) | constant value | none (default optional) | `[space]`: no; template: `--flag <literal>` if a default exists, else excluded from the template and treated as a standalone-only CLI arg (required if non-`Option`, optional if `Option`) |
| `tune` | sampled by argtuner | bool: none; float/int: `min` AND `max`; string/other: `choices` | `[space]`: yes; template: `--flag {name}` placeholder |
| `injected` | supplied per-trial by argtuner | `value_name` must be **exactly** `"trial_dir"` or `"trial_id"` | `[space]`: no; template: `--flag {value_name}` placeholder |
| `cli` | operational flag, CLI-only | none | `[space]`: no; template: excluded. Replaces `skip = true` |

### Compile-time validation (in the derive)
- unknown `role` string → error.
- **Strict per-role attribute matrix** — any prohibited attribute → `syn::Error` (dead attributes are rejected, not silently ignored; `long` is allowed on every role):

  | role | allowed | prohibited |
  |---|---|---|
  | `fixed` | `default` | `min`, `max`, `step`, `log`, `choices`, `parent`, `parent_values`, `value_name` |
  | `tune` | `default`, `min`, `max`, `step`, `log`, `choices`, `parent`, `parent_values` | `value_name` |
  | `injected` | `value_name` (whitelist `["trial_dir", "trial_id"]`) | `default`, `min`, `max`, `step`, `log`, `choices`, `parent`, `parent_values` |
  | `cli` | `default` | `min`, `max`, `step`, `log`, `choices`, `parent`, `parent_values`, `value_name` |

  Notes: `default` is prohibited on `injected` (argtuner supplies the value; a default is dead). `default` is *allowed* on `cli` (it sets the standalone CLI default and prevents `from_matches` panics on absent non-`Option` flags); a non-`Option` `cli` field **without** a default is itself an error.
- `role = "tune"` on non-bool without (`min` && `max`) or `choices` → error. Kind is classified on the **unwrapped** inner type, so `Option<f64>` with `min`/`max` and `role = "tune"` passes.
- **`ParamKind::Bool` (incl. `Option<bool>`) with `role = "tune"`: reject `min`/`max`/`step`/`log`/`choices`** → error. A tuned bool is a bare toggle; numeric constraints are a category error caught at compile time. (`parent`/`parent_values`/`default` remain allowed.)
- `role = "injected"` requires `value_name` in the hardcoded whitelist `["trial_dir", "trial_id"]` (must match `argtuner_common::PLACEHOLDER_*`; kept in sync by tests) → error otherwise. No arbitrary injection keys accepted.
- removed `skip` key → error suggesting `role = "cli"`.

### Unchanged
- `ParamKind` (Float/Int/Choice/Bool/Other) stays as *structural* type info; `role` is orthogonal.
- Generated TOML (`SpaceParam` serialization) is unchanged → tuner side (`src/search_space/mod.rs`, `src/inspect.rs`, `src/trial/*`) is untouched.
- clap arg generation is unchanged for every field regardless of role (standalone CLI still works); bool flag-style parsing unchanged.

## File-by-file changes

### 1. `crates/argtuner-sdk/src/lib.rs`
- Add `pub enum ParamRole { Fixed, Tune, Injected, Cli }` (`Debug, Clone, Copy, PartialEq, Eq`).
- `ParamHint` (~line 227): replace `pub skip: bool` with `pub role: ParamRole`; update field docs.
- `is_reserved()` (~258): → `matches!(self.role, ParamRole::Injected)`.
- `is_tunable()` (~266): → `matches!(self.role, ParamRole::Tune)` (delete skip/reserved/kind logic).
- `render_template_command` (~321): switch on role — `Tune` → placeholder `{name}`; `Injected` → placeholder `{value_name}`; `Fixed` + default → literal; `Fixed`/`Cli` w/o default → excluded. **Fixed-bool special case:** for `ParamKind::Bool`, emit the bare `--flag` when `default == true` and emit nothing when `default == false` (or absent) — never `--flag true/false`. This is safe for **both** `bool` and `Option<bool>` because the derive (below) applies flag-style parsing to every bool, so a bare `--flag` always parses (`num_args(0..=1).default_missing_value("true")` → `true`/`Some(true)`, absent → clap default/`None`).
- `render_template_toml` (~442): unchanged (already filters `is_tunable()`).
- Update `ParamKind::Bool` doc (~219) and `ParamHint` doc comments. SDK unit test (~650) unaffected.

### 2. `crates/argtuner-derive/src/lib.rs`
- `ParamAttrs` (~252): add `role: Option<String>`; remove `skip: bool`.
- `parse_param_attrs` (~265): parse `role`; return `Result<ParamAttrs, syn::Error>` so the removed `skip` key and bad values become compile errors (`syn::Error::new_spanned`).
- **Kind classification unwraps `Option<T>`** (~74-78): compute `is_bool`/`is_float`/`is_int`/`is_string` from the unwrapped `inner_ty` (e.g. `Option<f64>` → `Float`, `Option<usize>` → `Int`, `Option<String>` → `String`, `Option<bool>` → `Bool`) so `role = "tune"` validation and `SpaceParam` serialization see the real kind.
- **All bools use flag-style parsing** (~174): apply `num_args(0..=1).default_missing_value("true")` + `value_parser!(bool)` to **every** `ParamKind::Bool` — plain `bool` *and* `Option<bool>` — removing the plain/Option divergence. Bare `--flag` → `true`/`Some(true)`, `--flag false` → `false`/`Some(false)`, absent → clap default/`None`. `from_matches` extraction (`get_one::<bool>().cloned()`) is unchanged and stays correct for both. This keeps template bare-flag rendering valid for every bool field.
- Derive loop: compute role token, run the validation rules above, emit `role: ::argtuner_sdk::ParamRole::*` in the `ParamHint` literal (remove `skip` emission at line 143).
- Update the crate doc-comment example (lines 11–28) to the new syntax.

- `examples/loss_pattern_generator/main.rs`: `pattern` → `role = "tune"` (+choices); `steps`, `noise`, `spike_prob`, `metric_key`, `epoch_time` → `role = "fixed"` (+ defaults); `checkpoint_dir` → `role = "injected"`.
- `examples/pareto_demo/main.rs`: `learning_rate` → `role = "tune"`; `batch_size` → `role = "tune"` (+choices); `checkpoint_dir` → `role = "injected"`.
- `examples/interactive_probe/main.rs`: `metric_key` → `role = "fixed"` (or leave default); `checkpoint_dir` → `role = "injected"`.

## Out of scope
- Free-form/unbounded string search space (`ParamKind::Other` stays non-tunable; `role = "tune"` on a string still requires `choices`).
