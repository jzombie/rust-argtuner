# `ParamRole` discoverability: `argtuner_sdk::prelude` + canonical `ParamRole::Variant`

Bare idents (`role = tune`) in the proc-macro attribute are opaque tokens rust-analyzer
can't resolve, so there's no autocompletion/hover for roles. Fix: introduce
`argtuner_sdk::prelude` as the single import surface, canonicalize all docs/examples on
`role = ParamRole::Variant`, expand `ParamRole` rustdoc, and keep the bare-ident fallback
in the derive. **SDK prelude only** — do NOT add `argtuner-sdk` as a dependency of the
`argtuner` CLI crate (preserves the clean break).

## 1. Add `pub mod prelude` in `crates/argtuner-sdk/src/lib.rs`

```rust
pub mod prelude {
    pub use crate::emit_metrics;
    pub use crate::init;
    pub use crate::init_with_args;
    pub use crate::is_tuning_active;
    pub use crate::{talkback_args, EventKind, MetricsBuilder, ParamHint, ParamKind, ParamRole, Params, Talkback};
}
```

`emit_metrics` is `#[macro_export]`; `pub use crate::emit_metrics;` re-exports it so
`use argtuner_sdk::prelude::*;` brings the macro in scope too. Do NOT include the `clap`/
`serde` re-exports. (`argtuner`'s crate gets no prelude and no new dependency.)

## 2. Expand `ParamRole` rustdoc (`crates/argtuner-sdk/src/lib.rs` ~210-226)

Per-variant docs gain: required `#[param(...)]` attributes, generated template behavior,
and `[space]` effect. Sketch:

- `Fixed` — "Constant baked into the template as `--flag <default>` (or a standalone-only
  CLI arg when no default). Requires: `default` optional. Template: literal; `[space]`: excluded."
- `Tune` — "Sampled by argtuner (`--flag {name}` placeholder). Requires: `min`+`max`
  (float/int) or `choices` (string); bools need neither. Template: placeholder; `[space]`: included."
- `Injected` — "Supplied per-trial by argtuner. Requires: `value_name = "trial_dir"`/`"trial_id"`.
  Template: `--flag {value_name}`; `[space]`: excluded."
- `Cli` — "Operational flag, excluded from template and space. Requires: non-`Option` fields
  need a `default`. Template: excluded; `[space]`: excluded."
Also add a `# Usage` line to the enum doc pointing at `use argtuner_sdk::prelude::*;` +
`role = ParamRole::Tune`.

## 3. Update derive messages to canonical form (bare idents still accepted)

`crates/argtuner-derive/src/lib.rs` `parse_role`:
- string-literal error → "string literals are no longer accepted for `role`; use
  `role = ParamRole::Tune` (or bare `role = tune`)"
- non-path error → "`role` must be an enum variant path like `role = ParamRole::Tune`
  (bare `role = tune` also works)"
- unknown-variant message stays. The unreachable fallback in `parse_param_attrs` (~479)
  updated to list `ParamRole::Fixed/Tune/Injected/Cli`.
No change to acceptance logic: bare idents and paths both still parse (fallback retained).

## 6. Create repo-root `AGENTS.md` (new file) — the SDK/tuner boundary guardrail

Add `AGENTS.md` at the workspace root (none exists today) so any AI agent or future
maintainer sees the rule before editing. Content (concise, directive-first):

- Workspace map: `argtuner` (root crate) = the **tuner CLI** (TUI, PTY, SQLite,
  samplers/schedulers); `crates/argtuner-sdk/` = the **lightweight training-side
  binding** training binaries link; plus `argtuner-derive`, `argtuner-common`,
  `mock-bin`, `deprecated`.
- **Hard rules**:
  - Never add `argtuner-sdk` as a dependency of the `argtuner` crate.
  - Never move SDK code into `argtuner` or re-export SDK items from it
    (`argtuner::init`, `argtuner::emit_*`, `argtuner::ParamRole`, …).
  - Never add heavy deps to `argtuner-sdk` (term-wm/ratatui, rusqlite, argmin,
    portable-pty, …) — the SDK stays dependency-light.
- **Why:** training/model binaries link `argtuner-sdk`; if SDK code ever lands in
  `argtuner`, every user's model transitively compiles and ships the entire tuner
  package, defeating the crate separation.
- Point consumers at `use argtuner_sdk::prelude::*;`.
