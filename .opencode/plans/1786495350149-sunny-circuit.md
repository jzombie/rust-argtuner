# Plan: Remove the per-window `<Box>` card wrapping in the Watch TUI

## Context
The recent macro port (`4f6ef1a "Initial macro port"`) gave each of the four window
types a `view()` returning `view! { <Box padding=1>{child}</Box> }` — a
`BoxComponent` that draws a bordered card (`╭──╮`, dark-gray) with 1-cell padding
under the window's header bar. User feedback: this nested card is "ridiculous and
pointless"; every component has an unnecessary box. **Decision (user): remove the
Box, keep the term-wm window layout** (focus, titles, drag, copy, keybindings).

Verified facts:
- `view!` / `<Box>` is used only in these 4 `view()` methods (src/cli/tui/mod.rs:356, 368, 380, 392); no other usage of `view!` or `BoxComponent` in the file.
- The WM draws a header per tiled window (no border), so the Box was the only border — removing it makes content render flush under the header.
- `impl_view_component!(X, child: ...)` delegates `desired_height`/selection/hitbox to the child field directly (not through `view()`), so dropping the Box does **not** change layout contracts or the copy pipeline (comment at mod.rs:342-348 documents this contract).
- `&mut C` implements `Component` via term-wm's blanket impl (the `view!` docs rely on it), so `view()` can return `&mut self.<child>` directly.

## Changes — all in `src/cli/tui/mod.rs`

1. **Import (line 31):** remove the `view,` entry so the `term-wm` import list becomes:
   ```rust
   use term_wm::{
       AppContext, ListComponent, Rect as WmRect, ScrollKeyMode, ScrollViewComponent,
       TextRendererComponent, ToggleItem, ToggleListComponent,
   };
   ```

2. **Comment block (lines 342-348):** rewrite to drop the "bordered card" wording:
   ```rust
   // Per-window views: each pane is a thin struct owning its stateful component
   // and exposing it through a `view()` that returns the child directly (the
   // window manager's header already frames the pane — no nested card border).
   // `impl_view_component!`'s `child:` form forwards the component lifecycle to
   // the per-frame view and delegates `desired_height` + selection/hitbox to the
   // child field, so variable-height content keeps its layout contract and the
   // copy pipeline (which reads selection off the focused window root) keeps
   // working.
   ```

3. **Four `view()` bodies** — replace the `<Box>` wrapping with the child reference:
   - `TrialsWindow::view` (355-357): `&mut self.sv`
   - `ChartsWindow::view` (367-369): `&mut self.sv`
   - `TextWindow::view` (379-381): `&mut self.sv`
   - `ToggleWindow::view` (391-393): `&mut self.list`
   e.g.:
   ```rust
   fn view(&mut self) -> impl Component<TermWmAction> + '_ {
       &mut self.sv
   }
   ```

No changes to the wrapper structs, `impl_view_component!` invocations, `AppComponent`,
`impl_component_delegate!`, the `mk_*` constructors, or the `view_tests`
(they assert delegation of height/selection to the child, unaffected by the Box).

No README change needed — the README documents window titles/keybindings, not the
card border styling.
